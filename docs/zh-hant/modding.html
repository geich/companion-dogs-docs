Companion Dogs：模組製作手冊

如何製作你自己的附加模組：一個新品種，或者一整個物種，作為獨立的創意工坊模組掛接到 Companion Dogs 上。

這本手冊是寫給做模組的人看的。如果你只是想玩，你要看的是另外兩本： 功能 講狗狗能做什麼， 品種 講品種本身。

本手冊假設你已經讀得懂 Lua，並且手上已經有一個附骨架與動畫的動物模型。美術流程不在這裡；第 3 節 列出模型檔案必須符合的條件，就到此為止。

這是一份公開的契約。 本手冊點名的一切，都是給模組外部呼叫用的。這裡沒有點名的東西屬於內部 實作，可能在任何版本裡不經通知就改掉。

1. 附加模組是什麼

附加模組就是一個普通的創意工坊模組，它宣告 require=CompanionDogs，並在載入時呼叫一個函式。它只 加入一個品種（若共用同一副身體，也可以是好幾個），除此之外什麼都不加。讓動物表現得像個夥伴的 一切，早就在基礎模組裡，而且是共用的。

基礎模組擁有：

  • 動畫狀態機、動畫組與骨架
  • 跟隨、尋路、戰鬥、狩獵、放牧、警戒、需求與日常照料
  • 全部介面：狗狗視窗、環形選單、右鍵選單、狗舍、地圖標記
  • 馴服、羈絆、繁殖、幼犬與混種
  • 沙盒選項，以及多人遊戲的同步

你的附加模組擁有：

  • 讓你的動物有別於卡拉梅洛的那些數值
  • 牠的身體模型、材質、肖像，以及若有的話，moodle 圖示
  • 牠會在世界的哪裡被找到
  • 牠的名字與說明，在你隨附的每一種語言裡

這個分工就是全部的重點。一個品種包只是幾百行 Lua，因為難的部分早就在跑了。

一個品種，一副樣貌。 品種就是一組數值加上一副樣貌。如果你想讓同一種動物的兩種顏色表現不同，那 就是兩個品種。如果你要兩種表現一模一樣的顏色，對基礎模組而言牠們仍然是兩個品種（兩個名字，狗舍裡 兩筆資料），而你會從一張共用的表把牠們寫出來，就像 CD: Cats 用牠五種毛色所做的那樣。

2. API 的各個版本

CD.API_VERSION 就是一個單純的數字。它一直只靠增添而變大，所以針對舊版本寫的附加模組，在較新的基 礎模組上一行都不必改，照樣載入。

API 基礎模組版本 增添了什麼
1 0.6.3 CD.registerBreed、生成註冊表、品種 moodle
2 0.6.6 huntFetchLevel、huntDeliverTimeoutMin、掛鉤 CD.onHuntDelivered
3 0.6.8 sentinelMult、barkNoiseMult、loyaltyDecayMult、掛鉤 CD.onUpkeepStress
4 0.6.9 alertModeLocked
5 0.7.0 skills、canBreed、huntMaxPrey、descKey、voices、CD.registerVoices

守衛裡要寫的數字，是你的附加模組真正需要的最低 API，而那張表裡對應的基礎模組版本，就是你要寫在 創意工坊頁面上的版本。從這張表取，而不是從你寫程式時基礎模組剛好是哪一版：只存在於開發版裡的欄 位，就是你的玩家沒有的欄位。

缺少的欄位會被靜靜忽略。 當欄位是數值時這沒關係：在較舊的基礎模組上，你的動物只是用正常音量吠 叫而已。當欄位是一道封鎖時就有關係了，因為那樣一隻絕不該打架的貓會從容地衝上去打。也就是說：數值 可以退而求其次，封鎖不行。若你的動物仰賴某道封鎖，就用引進它的那個 API 來守衛，並讓附加模組在更舊 的一切上完全不動作。

3. 動手之前要準備什麼

基礎模組，0.6.3 或更新。 底下的一切都是往它裡面發出的呼叫。

一個蒙皮完成的模型。 你的動物需要自己的 .glb，放在 media/models_X/Skinned/ 底下，而那個檔案 必須帶著完整的 21 個 Rac_* 動畫片段。片段不會在模型檔案之間繼承：只有十五個片段的模型，會給 你一隻在第一次被要求做其餘六個動作時就僵住的動物。模型還必須維持在 60 根骨頭以下，且最上層節點 為單位矩陣，否則引擎每一格畫面都會擲出例外，動物會被畫成一團黑色污漬。

如果你還沒有模型，仍然可以把 CD.applyDogModel 指向基礎模組的某一副身體，然後把其餘全部寫出來並測 試。動物看起來會像卡拉梅洛，但本手冊裡的每一個系統都跑得動。

身體的一張材質，以及狗舍視窗用的一張肖像。

在寫任何程式碼之前先決定一件事： 你的動物是一個*品種*，還是一個*物種*？品種是數值不同的狗。物 種是根本沒有某些工作的動物。這個差別不是外觀問題，它會決定你要寫哪些欄位，而第 7 節談的正是它。

4. 一個附加模組的檔案

這是 CD: Pug，已發佈的附加模組裡最小的一個，只留下要緊的部分：

CompanionDogsPug/
  42/
    mod.info
    icon.png
    poster.png
    media/
      models_X/Skinned/Pug_Body.glb
      scripts/models_pug.txt
      textures/Body/Pug.png
      textures/CDPortrait_pug.png
      lua/shared/CompanionDogsPug_Breed.lua
      lua/shared/Definitions/animal/PugDefinitions.lua
      lua/shared/Definitions/animal/CompanionDogsPug_Parts.lua
      lua/client/CompanionDogsPug_Moodle.lua
      lua/shared/Translate/EN/IG_UI.json
      lua/shared/Translate/PTBR/IG_UI.json
  common/

還有 mod.info：

id=CompanionDogsPug
name=CD: Pug
description=Pugs for Companion Dogs. REQUIRES the Companion Dogs mod (0.6.8 or newer).
poster=poster.png
icon=icon.png
require=CompanionDogs
modversion=0.1.0
pzversion=42.19.0
versionMin=42.18.0

require=CompanionDogs 是關鍵的一行。它保證基礎模組的 Lua 全部在你的之前跑完，每個階段都是如 此：先 shared，接著 client，接著 server。少了它，你的檔案可能先載入，那時每一次 CD. 呼叫都是在對 nil 取索引。

versionMin 沒辦法表達「需要 Companion Dogs 0.6.8」。 那個欄位是*遊戲*版本的門檻，別無其他， 而 mod.info 裡並不存在寫相依模組版本的欄位。基礎模組的下限由下一節的守衛強制執行，並透過你的說明告 訴玩家。把它用文字寫在那裡，否則玩家得到的唯一徵狀，就是一隻永遠不出現的動物。

5. 版本守衛

把這段放在你附加模組每一個 Lua 檔案的最上面，數字換成你的附加模組真正需要的那個：

local CD = CompanionDogs
if not (CD and CD.registerBreed and (CD.API_VERSION or 0) >= 3) then return end

基礎模組不存在或太舊時，檔案在第二行就返回了。這時附加模組什麼都不做：沒有品種，沒有生成，沒有 moodle，日誌裡連一行都沒有。這份安靜是刻意的。載入到一半的附加模組比根本沒載入更糟，因為玩家會拿到 一隻有名字卻沒有行為的動物。

守衛是逐檔案的，而每個檔案守衛自己要用的東西。PugDefinitions.lua 需要模型輔助函式，於是它守衛那 些：

if not (CompanionDogs and CompanionDogs.applyDogModel and CompanionDogs.DOG_SOUNDS) then return end

永遠不要自己建立那個全域變數。 附加模組裡的 CompanionDogs = CompanionDogs or {} 會把一個不存在 的基礎模組變成一張只搭了一半的表，於是下游每一道守衛都會在不該通過的時候通過。去讀那個全域變數，永 遠不要往裡面寫。

6. 註冊品種

一次呼叫，在一個 shared 檔案裡：

CD.registerBreed({
    key = "pug",
    engineBreed = "pug",
    typePrefix = "pug",
    nameKey = "IGUI_PD_Breed_pug",
    litter = { 1, 2 },
    xpMult = { scent = 1.5, combat = 1, obedience = 2.0, hunt = 1.2, herding = 1.0 },
    combatPower = 0.15,
    lethalityCurve = { min = 0.40, max = 1.3 },
    canKill = false,
    canKnockdown = false,
    combatStressMult = 0.9,
    panicThreshold = 0.70,
    bagMult = 0.6,
    sentinelMult = 1.35,
    barkNoiseMult = 1.5,
    alertModeLocked = true,
    loyaltyDecayMult = 0,
    geneRange = {
        strength       = { 0.00, 0.10 },
        aggressiveness = { 0.05, 0.20 },
        resistance     = { 0.00, 0.15 },
        stress         = { 0.55, 0.85 },
    },
    spawns = {
        { id = "pughouse", class = "house", suffix = "|pg", breed = "pug",
          chance = function() return CD.strayChancePerHouse() / CD.PUG_HOUSE_RARITY end },
    },
})

這次呼叫會把品種塞進去，註冊牠的三個動物類型，重建繁殖順序好讓你的動物參與雜交，並註冊生成步驟。

有問題的定義會回傳 nil 而不是擲出錯誤，所以一個閃失絕不會把載入一起拖垮。每一次拒絕都會印出一行 點名的紀錄，所以你第一次註冊品種時要去讀日誌。

必填欄位

欄位 是什麼
key 你這個品種的識別字，在所有模組之間唯一。發佈之後永不更動。
typePrefix 三個動物類型的前綴：<前綴>pup、<前綴>female、<前綴>male。它決定身體網格。
nameKey 顯示名稱的翻譯鍵。
xpMult 每項技能的學習速度：scent、combat、obedience、hunt、herding。1.0 是正常值。
combatPower 牠下嘴有多重。卡拉梅洛是 0.20，能打的品種在 1.0 以上。
lethalityCurve { min, max }，傷害從戰鬥 0 級到戰鬥 10 級是怎麼成長的。
geneRange 四個基因出生時的範圍：strength、aggressiveness、resistance、stress。每個都是 0 到 1 之間的 { 下限, 上限 }。

選填欄位

欄位 預設值 作用
engineBreed 與 key 相同 交給引擎的品種名，它決定材質。每個品種唯一。
descKey IGUI_PD_BreedDesc_<key> 說明文字的鍵。當幾個品種共用一段說明時，把牠們指向同一個鍵。
litter 基礎模組的值 每一胎幼犬的 { 下限, 上限 }。
canKill true false 表示牠能磨損喪屍，但永遠不會補上致命一擊。
canKnockdown false true 讓牠能把喪屍撞倒。
combatStressMult 1 一場打鬥對牠來說有多少壓力代價。
panicThreshold 基礎模組的值 牠停止戰鬥的壓力水準。panicImmune = true 表示永遠不停。
bagMult 1 鞍袋容量的倍率。
puppySize 0.6 幼犬的絕對視覺縮放。小型品種一定要設定它，否則幼犬一出生就是成年體型。
sentinelMult 1 乘在最終的警戒半徑上。
barkNoiseMult 1 縮放警報吠叫的半徑與音量。它縮放噪音，而不是製造噪音：沙盒的噪音選項關掉之後，沒有哪個品種會用吠叫招來喪屍。
loyaltyDecayMult 1 乘在忠誠度每日的衰減上。0 表示羈絆永不淡去。
alertModeLocked false 動物被鎖在全面警戒：主人在任何地方都無法把牠切到安靜或靜音。當吵鬧的警報就是設計本身時才用。
huntFetchLevel 6 從這個狩獵等級起，牠會把獵物叼回給主人。
huntDeliverTimeoutMin 5 牠放棄交付之前還會再試多少遊戲分鐘。
idleAnimMs 基礎模組的值 待機動畫視窗的長度，單位毫秒。當你的片段比狗的短時要設定它，否則循環會重新開始並在動作中途被切掉。
restAnim true false 讓動物在待命與守衛時保持站著，而不是趴下。
voices 狗的聲音 { bark, growl, idle, wildbark, pet }。見下文。
skills、canBreed、huntMaxPrey 全部開啟 結構性的封鎖。第 7 節。

你加進定義裡的數值與旗標，可以用 CD.breedNumber(animal, 欄位) 和 CD.breedFlag(animal, 欄位) 讀 回來。比起自己去讀 CD.getBreedDef(animal).欄位，優先用這兩個：牠們替你處理缺少的欄位，而且在基礎 模組挪動之後依然可用。

聲音

不同的物種不說同一種語言。少了 voices，你的貓會吠：

CD.registerVoices({
    CDCatMeow = "bark", CDCatGrowl = "bark", CDCatPurr = "bark",
    CDCatPet = "fx", CDCatMeowAmbient = "ambient",
})
voices = { bark = "CDCatMeow", growl = "CDCatGrowl", idle = "CDCatPurr",
           wildbark = "CDCatMeowAmbient", pet = "CDCatPet" },

CD.registerVoices 不是可有可無的裝飾。少了它，聲音照樣會響，但會無視玩家的分類音量滑桿與遊戲本身 的音效音量，而這是一種沒人會回報的故障，因為什麼都不像壞掉。你在 voices 裡漏掉的鍵會退回狗的聲 音，那正是你在狗的品種上想要的，也永遠不是你在另一個物種上想要的。

7. 整套關掉一個系統

五項技能就是五個系統，一對一：

技能 牠就是哪個系統
scent 警戒：察覺喪屍並提醒你
combat 打鬥、守衛模式與自衛
obedience 才藝樹
hunt 狩獵，外加牠給主人的採集加成
herding 照看柵欄裡的牲口

物種不是數值比較差的狗。牠是根本沒有其中某些工作的動物。所以牠宣告自己沒有什麼：

skills = { combat = false, herding = false },
canBreed = false,
huntMaxPrey = "tiny",

不寫或寫 true，都表示這隻動物擁有該技能，所以你只要寫出你要拿掉的那幾項。

關掉一項技能會同時做三件事：系統永遠不執行，該技能永遠不獲得經驗，牠的長條連同指令一起從介面上 消失。三件一起。只把長條藏起來，技能還是會在沒人看得到的地方長；只鎖住系統，長條就會永遠卡在零。

canBreed = false 放在表外面，因為繁殖既沒有長條也沒有經驗。而且它是徹底的：這隻動物不會受孕，永遠 不會被選為配偶，連自己的品種也不會配。

huntMaxPrey 是一場確實存在的狩獵之內的上限，這和 hunt = false 是兩回事。它接受 "tiny"（小 鼠、大鼠、松鼠）、"small"（兔子、浣熊）或 "large"（鹿，預設值，沒有上限）。超過上限的獵物對你的 動物來說是看不見的：牠不會追，甚至不會去指。不在這個階梯上的值會退回 "large"，並在日誌裡印出一行 點名的紀錄。

被封鎖的動物不會拿到一顆變灰的按鈕。 那個選項會從環形選單、右鍵選單與視窗裡消失，伺服器端的拒絕 也是安靜的。一圈寫著「牠無視了命令」的光暈會是謊話，因為這並不是不服從。請在你的品種說明裡解釋這個 設計。這也正是這些欄位一個都不會帶來新翻譯鍵的原因。

8. 動物定義

引擎把網格綁在動物類型上，而不是綁在品種上，所以你的品種需要自己的三個類型。這是附加模組裡機械 性的一塊，最短的路是複製一個現成附加模組的檔案再改名。

三個部分，放在 Definitions/animal/ 底下的一個 shared 檔案裡：

AnimalDefinitions.stages["pug"] = {}
AnimalDefinitions.stages["pug"].stages = {}
AnimalDefinitions.stages["pug"].stages["pugpup"] = {}
AnimalDefinitions.stages["pug"].stages["pugpup"].ageToGrow = 3 * 30
AnimalDefinitions.stages["pug"].stages["pugpup"].nextStage = "pugfemale"
AnimalDefinitions.stages["pug"].stages["pugpup"].nextStageMale = "pugmale"
AnimalDefinitions.breeds["pug"].breeds["pug"].texture = "Pug"
AnimalDefinitions.breeds["pug"].breeds["pug"].textureMale = "Pug"
AnimalDefinitions.breeds["pug"].breeds["pug"].rottenTexture = "Raccoon_Rotting"
AnimalDefinitions.breeds["pug"].breeds["pug"].invIconMale = "CDDogPaw_64"
AnimalDefinitions.breeds["pug"].breeds["pug"].invIconMaleDead = "CDDogPawDead_64"
local pugfemale = {}
CD.applyDogModel(pugfemale, "Pug_Body")
CD.applyDogBehaviour(pugfemale)
pugfemale.female = true
pugfemale.babyType = "pugpup"
pugfemale.minSize = 1.5
pugfemale.maxSize = 2.0
pugfemale.minWeight = 5
pugfemale.maxWeight = 8
pugfemale.wildFleeTimeUntilDeadTimer = CD.STRAY_NO_BLEEDOUT
pugfemale.breeds = AnimalDefinitions.breeds["pug"].breeds
pugfemale.stages = AnimalDefinitions.stages["pug"].stages
pugfemale.genes = AnimalDefinitions.genome["dog"].genes
AnimalDefinitions.animals["pugfemale"] = pugfemale

基礎模組給你的輔助函式：

輔助函式 牠替你填好什麼
CD.applyDogModel(t, "Body_Model") 身體模型、骨架、屠宰用材質與動畫組
CD.applyDogBehaviour(t) 一個夥伴所需的每一個引擎行為旗標
CD.applyDogAvatar(t) 動物視窗的肖像鏡頭
CD.DOG_SOUNDS 腳步聲與擬音的共用表
CD.STRAY_NO_BLEEDOUT 讓受驚的流浪動物不至於失血而死的那個值
CD.defineDogParts(typePrefix, engineBreed) 三個成長階段的屠宰部位

四條並不明顯的規則：

動畫組必須維持是 "raccoon"。 CD.applyDogModel 會設定它。分支出去的動畫組不會載入它自己的狀態 機，而沒有狀態機的動物就是一隻釘在原地的動物。

重用基因組： AnimalDefinitions.genome["dog"].genes。不要自己另外寫一份。

永遠不要宣告 mate。 有了它，引擎會在任何動物區域內跑牠自己的原生交配，那套邏輯無視本模組的繁殖 封鎖與沙盒選項，並產出沒有羈絆的幼犬。基礎模組會在開機時清掉這個欄位當作安全網，但別倚賴它。

部位是必要的。 單獨一個檔案裡三行：

if CompanionDogs and CompanionDogs.defineDogParts then
    CompanionDogs.defineDogParts("pug", "pug")
end

少了牠們，屠宰你的動物會讓原版程式碼當掉，因為它按類型與品種去索引部位定義，然後踩到 nil。

小型動物需要調整肖像鏡頭。 CD.applyDogAvatar 裡的肖像縮放是照著狗校準的，而頭像的 zoom 是放大 倍率：動物越小，數字越大。把 zoom 除以相對於狗的體型比例，再把偏移量乘上這個比例，否則你的動物會小 小地縮在自己肖像的底部。

9. 模型腳本

media/scripts/ 底下的一個檔案，正是它告訴遊戲你的模型存在：

module Base
{
    model Pug_Body
    {
        mesh = Skinned/Pug_Body,
        shader = animalEffect,
        static = false,
        animationsMesh = PugAnim,
        attachment head
        {
            offset = -0.0061 0.1671 0.0507,
            rotate = -179.0 -5.0 95.0,
            bone = Dummy01,
        }
    }

    animationsMesh PugAnim
    {
        meshFile = Skinned/Pug_Body,
        keepMeshAnimations = true,
    }
}

keepMeshAnimations = true 是讓你模型檔案裡的動畫片段保持可用的那一行。少了它，模型載得進來卻永遠 不會動。

head 附著點是帽子之類東西所在的位置。如果你想讓鞍袋合你的動物的身，就用同樣的方式在脊椎骨上加 saddlebags_l、saddlebags_r 與 saddlebags_c。這些數字是在遊戲裡看著動物一點一點挪出來的，而不 是量模型量出來的：一個數學上置中的袋子，放在有毛的身體上照樣看起來歪。

10. 這隻動物會在哪裡出現

流浪動物是按建築、按區塊抽出來的，就在那個區塊第一次載入的時候。你把自己的抽取寫成一串步驟，要嘛放 在品種定義裡的 spawns，要嘛透過 CD.registerStraySpawns(清單)。

spawns = {
    { id = "pughouse", class = "house", suffix = "|pg", breed = "pug", indoor = 85,
      chance = function() return CD.strayChancePerHouse() / CD.PUG_HOUSE_RARITY end },
    { id = "pugpetvet", class = "petvet", suffix = "|pv", breed = "pug",
      chance = function() return CD.PUG_PETVET_CHANCE * CD.dogSpawnMultiplier() end },
},
鍵 是什麼
id 這個步驟的名字，給你自己的日誌用
class 牠在哪個建築類別上抽
chance 一個回傳百分比的函式。是函式而不是數字，這樣它才跟得上即時的沙盒倍率。
suffix 持久化儲存的鍵。在整個生態裡唯一，而且永不更動。
breed 要生成的品種鍵
gate 選填函式，回傳布林值，會在抽取之前檢查。哈士奇用的是 CD.isWinter。
indoor 在建築內部而不是街上出生的百分比。預設 35。

把你的機率乘上 CD.dogSpawnMultiplier()，或者把 CD.strayChancePerHouse() 除以你自己的稀有度。無論 哪一種，玩家的沙盒設定都還有效，而你要是寫一個光禿禿的數字，它就失效了。

indoor 是偏好而不是承諾：那個區塊裡沒有空著的室內地磚的建築，會退回到外面的地磚。

建築類別

基礎模組註冊了四個，你可以直接拿來用：

類別 符合什麼
house 不是店面的住宅建築
police 警察局之類
petvet 寵物店與獸醫診所
farm 農場建築，而且允許出現在城鎮之外

如果沒有一個合用，就註冊你自己的：

CD.registerBuildingClass("mineshaft", function(def) return def:isX() end,
                         { skipUrbanGate = true })

比對函式會拿到建築定義，並在一次受保護的呼叫裡執行，所以它裡面的閃失沒辦法把區塊載入拖垮。 skipUrbanGate 讓這個類別可以在非城鎮的區塊裡抽，農場或林中小屋正需要這個。別去動 exclusive：基 礎模組的那幾個類別彼此互斥，而附加模組的類別在設計上是加成的，會疊在牠們之上再比對一次。

已經被佔用的後綴

後綴是「這棟建築已經抽過了」這筆紀錄所用的鍵的一部分。兩個模組用同一個後綴，會互相毀掉對方的抽取結 果。

每個後綴都以一根直線開頭。下面這些已經在用：

  • 基礎模組： 空後綴，以及 g、h、hv、bc
  • 羅威納： rw、r
  • 杜賓： db、dm
  • 拉布拉多： lb、lk
  • 巴哥： pg、pv
  • 貓： ct、cv、ctw、cvw、cto、cvo、ctc、cvc、ctx、cvx

挑一個沒人用的，然後再也別碰它。

11. 品種 moodle

moodle 是一個 client 檔案。你往 CD.DogMoodles 裡追加一張表，基礎模組負責繪製、追蹤與清理：

CD.DogMoodles[#CD.DogMoodles + 1] = {
    id = "shadow",
    breed = "pug",
    nameKey = "IGUI_PD_Moodle_Shadow",
    descKey = "IGUI_PD_Moodle_Shadow_desc",
    icon = "CD_Moodle_Shadow",
    fg = "CD_MoodShadowFG",
    tintR = 0.92, tintG = 0.52, tintB = 0.68,
    condition = function(player, dog)
        if not dog or dog:isDead() then return 0 end
        if CD.getBreed(dog) ~= "pug" then return 0 end
        if CD.isDisloyal(dog) then return 0 end
        return 1
    end,
    apply = function(player, dog, elapsedMin)
        CD.relieveMood(player, CD.moodleReliefPerMin() * elapsedMin)
    end,
}

condition 回傳等級，或者回傳 0 表示「不顯示」。apply 被呼叫時會拿到距離上一次呼叫過了多少遊戲分 鐘，所以請把你的效果乘上 elapsedMin，不要假設有個固定節拍。

圖示要隨附六種尺寸，從 32 到 128 像素。介面會依玩家的縮放挑尺寸，少一個尺寸就是一個空方塊。

自訂 moodle 是當成疊加層繪製的，並沒有走遊戲本身的 moodle 系統，因為那個系統不接受來自模組的新項 目。這一塊已經替你處理好了，但這也是為什麼 moodle 出現在模組自己的橫條裡，而不是混在原版那幾個之 中。

12. 掛鉤

基礎模組在伺服器上呼叫的兩份函式清單。請從一個 shared 檔案往裡面追加。每個處理函式都在自己那一 次受保護的呼叫裡執行，所以壞掉的附加模組沒辦法把基礎模組一起拖垮。

CD.onHuntDelivered，從 API 2 起，在動物把獵物放到主人腳邊之後立刻呼叫：

CD.onHuntDelivered[#CD.onHuntDelivered + 1] = function(animal, owner)
    -- server side, so this is the right place to write mod data
end

CD.onUpkeepStress，從 API 3 起，在每個照料週期呼叫，時機是基礎模組已經把未滿足需求帶來的壓力加 好、還沒寫回去之前。回傳一個數字，它會被加進總和：

CD.onUpkeepStress[#CD.onUpkeepStress + 1] = function(animal, needsStress)
    return CD.pugHeatRatio(animal) * CD.PUG_HEAT_STRESS_MAX
end

這是附加模組能影響動物持續壓力的唯一途徑。照料會在每個週期重新計算並覆寫這個值，所以你從外面寫 進去的任何東西，下一個節拍就沒了。對於來自環境的狀態，像是炎熱、寒冷、下雨，這才是對的工具。

多人遊戲的規則，一句話：客戶端永遠不寫模組資料。 客戶端這邊的寫入會在下一次同步時蓋掉伺服器的副 本，而徵狀要過好幾分鐘才在毫不相干的地方冒出來。把這份工作放到伺服器端的檔案裡做，或者放進這些本來 就跑在伺服器上的掛鉤裡。

13. 翻譯鍵

每個語言資料夾底下隨附一份 IG_UI.json，路徑是 media/lua/shared/Translate/<LANG>/。基礎模組隨附了 十四種：EN、PTBR、CH、CN、DE、ES、FR、IT、JP、KO、RU、TH、UA、VI。

一個品種需要的鍵：

鍵 顯示在哪裡
IGUI_PD_Breed_<key> 品種名，出現在模組介面各處
IGUI_PD_BreedDesc_<key> 動物卡片上的說明
IGUI_Breed_<engineBreed> 遊戲本身畫面裡的品種名
IGUI_AnimalType_<type> 你那三個類型各一個
你的 moodle 鍵 名稱與說明，如果你有 moodle 
{
    "IGUI_Breed_pug": "Pug",
    "IGUI_AnimalType_pugmale": "Pug (male)",
    "IGUI_AnimalType_pugfemale": "Pug (female)",
    "IGUI_AnimalType_pugpup": "Pug (puppy)",
    "IGUI_PD_Breed_pug": "Pug",
    "IGUI_PD_BreedDesc_pug": "The house dog: the first companion whose worth is not fighting."
}

有兩件事會咬你。翻譯字串裡一個字面的百分號會讓顯示它的那個畫面當掉，因為格式化器把它讀成了佔位 符。還有，帶著位元組順序記號的語言檔案編譯不過，而且報出來的錯誤點名的是另一個檔案，不是真正壞 掉的那個。

14. 存檔記住的東西

你的三個識別字會被寫進存檔檔案，並且從此一直被讀回來：

  • key，存在你每一隻動物身上的品種識別字
  • typePrefix，它構成了引擎所儲存的那些動物類型
  • suffix，「已經抽過了」這份儲存的鍵，每個生成步驟一個

這三個在發佈之後都不能再改名。 改掉一個 key，會讓那個品種所有還活著的動物變成孤兒。改掉一個 suffix，會讓每一份現有存檔裡的每一棟建築重新抽一次，一個玩了好幾個月的世界會突然塞滿你的動物。

這種重抽唯一有用的時候，就是它本身正是目的：CD: Cats 刻意給牠四種新毛色配了新後綴，正是為了讓牠們在 已經在跑的世界裡開始出現，而原本那隻黑貓保留了自己的歷史後綴，沒有重抽。

從一份還有該品種活體動物的存檔裡移除附加模組，就等於把牠們弄丟。 引擎會丟棄自己不再認得其類型的 動物。基礎模組不會當掉，羈絆與狗舍都會乾淨地降級，但那隻動物沒了。像每一個已發佈的附加模組那樣，把 這件事寫在你的創意工坊頁面上。

未知的品種是降級而不是失敗。 如果你的附加模組不在，基礎模組面對所有相關的詢問都會退回預設品種， 所以一份沒有你的模組也照樣打得開的存檔是讀得出來的。

15. 發佈之前

  • 守衛在每一個 Lua 檔案裡都有，而且寫的是你真正用到的那個 API。
  • 基礎模組的版本下限用文字寫在你的說明裡。versionMin 說不出這件事。
  • 你在第一次載入時讀了日誌。否則 CD.registerBreed 會安靜地拒絕，而每一次拒絕都會印出一行點名的紀 錄。
  • CD.defineDogParts 確實有被呼叫。屠宰一隻你自己的動物，看看不會當。
  • 你的 key、typePrefix 與生成後綴都是唯一的，而且你願意永遠用下去。
  • 小型品種設定了 puppySize，而且你親眼看過一隻幼犬來證明這一點。
  • 如果牠是另一個物種，CD.registerVoices 確實有被呼叫而且 voices 填好了，否則牠會吠。
  • moodle 圖示六種尺寸都在。
  • 你隨附的每個語言資料夾都有全部的鍵。少一個鍵，畫面上就會顯示出光禿禿的鍵名。
  • 你在多人遊戲裡測過，而不只是單人。位置、歸屬與模組資料在那邊的表現是不一樣的。
  • 你的創意工坊頁面警告了不要從還有活體動物的存檔裡移除這個附加模組。

16. 常見錯誤

「我的動物從來不出現。」 幾乎總是守衛：你的附加模組需要一個已安裝的基礎模組沒有的 API，所以牠照 設計處於不動的狀態。拿你的 API 數字和第 2 節的表對一下。

「牠出現了，但僵住不動。」 動畫組不是 "raccoon"，或者你的模型缺了片段。兩者都會表現成一隻永遠 站著不動的動物。

「牠被畫成一團黑色污漬，日誌灌爆。」 模型的骨頭超過 60 根。

「屠宰牠會當。」 CD.defineDogParts 沒被呼叫。

「幼犬一出生就是成年體型。」 一個沒設定 puppySize 的小型品種。這個值是絕對的，而且每一輪掃描都 會重新套用，所以類型本身的尺寸範圍救不了你。

「我的兩個品種老是變成對方。」 牠們共用了 engineBreed。前綴挑的是網格，可以由一個家族共用； engineBreed 挑的是材質，正是它在那個家族內部做區分，所以它必須每個品種唯一。

「聲音有響，但無視音量滑桿。」 那個聲音沒有呼叫過 CD.registerVoices。

「單人裡沒問題，上了伺服器就亂來。」 有東西在客戶端寫模組資料。把它挪到伺服器端去。

「我明明關了戰鬥，牠還是跟喪屍打起來了。」 牠所執行的基礎模組比 API 5 更舊，那時這個欄位還不存 在，於是被安靜地忽略了。這正是守衛必須擋下來、而不是降級的那種情況。
