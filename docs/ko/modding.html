Companion Dogs: 모딩 설명서

나만의 애드온 만드는 법. 새로운 품종, 또는 종 전체를 Companion Dogs에 맞물리는 별도의 워크샵 모드로 만듭니다.

이 설명서는 모드를 쓰는 사람을 위한 것입니다. 그냥 플레이하고 싶다면 필요한 것은 나머지 두 권입니다. 개가 무엇을 하는지는 기능, 품종 자체는 견종를 보세요.

Lua를 읽을 줄 알고, 리그와 애니메이션이 붙은 동물 모델을 이미 가지고 있다고 가정합니다. 아트 파이프라인은 여기에 없습니다. 3절이 모델 파일이 만족해야 할 조건을 나열하고, 그 이상은 다루지 않습니다.

이것은 공개된 계약입니다. 이 설명서가 이름을 붙인 것은 모두 모드 바깥에서 호출되라고 있는 것입니다. 여기에 이름이 없는 것은 내부용이며, 어떤 버전에서든 예고 없이 바뀔 수 있습니다.

1. 애드온이란 무엇인가

애드온은 require=CompanionDogs를 선언하고 로드 시점에 함수 하나를 호출하는 평범한 워크샵 모드입니다. 추가하는 것은 품종 하나(몸을 공유한다면 여럿)뿐이고, 그 외에는 아무것도 없습니다. 동물이 동반자처럼 행동하게 만드는 모든 것은 이미 베이스 모드 안에 있고, 공유됩니다.

베이스가 가진 것:

  • 애니메이션 상태 기계, 애님셋, 스켈레톤
  • 따라오기, 길찾기, 전투, 사냥, 가축 돌보기, 보초, 욕구, 유지 관리
  • 인터페이스 전체. 개 창, 방사형 메뉴, 상황 메뉴, 견사, 지도 표시
  • 길들이기, 유대, 번식, 강아지, 잡종
  • 샌드박스 옵션과 멀티플레이 동기화

여러분의 애드온이 가진 것:

  • 여러분의 동물을 카라멜루와 다르게 만드는 숫자들
  • 몸 모델, 텍스처, 초상화, 그리고 있다면 무들 아이콘
  • 세계 어디에서 발견되는지
  • 이름과 설명을, 함께 배포하는 모든 언어로

이 분담이 요점 전부입니다. 품종 팩은 Lua 몇백 줄이면 됩니다. 어려운 부분은 이미 돌아가고 있으니까요.

한 품종에 한 모습. 품종이란 숫자 묶음 하나에 모습 하나입니다. 같은 동물의 두 색깔이 서로 다르게 행동하길 원한다면 그것은 두 품종입니다. 똑같이 행동하는 두 색깔을 원해도, 베이스가 보기에는 여전히 두 품종이며(이름 둘, 견사 항목 둘), CD: Cats가 다섯 가지 털색으로 하는 것처럼 공유 테이블 하나에서 작성합니다.

2. API 버전

CD.API_VERSION은 단순한 숫자입니다. 지금까지 오직 더하는 방식으로만 커져 왔기 때문에, 예전 버전을 겨냥해 쓴 애드온도 더 새로운 베이스에서 한 줄도 고치지 않고 계속 로드됩니다.

API 베이스 버전 무엇이 추가되었나
1 0.6.3 CD.registerBreed, 스폰 레지스트리, 품종 무들
2 0.6.6 huntFetchLevel, huntDeliverTimeoutMin, 훅 CD.onHuntDelivered
3 0.6.8 sentinelMult, barkNoiseMult, loyaltyDecayMult, 훅 CD.onUpkeepStress
4 0.6.9 alertModeLocked
5 0.7.0 skills, canBreed, huntMaxPrey, descKey, voices, CD.registerVoices
6 0.7.1 species, CD.registerSpecies

가드에 적을 숫자는 여러분의 애드온이 실제로 필요로 하는 가장 낮은 API입니다. 그리고 그 표에 적힌 베이스 버전이 워크샵 페이지에 밝힐 숫자입니다. 작성하던 시점에 베이스가 무엇이었는지가 아니라 이 표에서 가져오세요. 개발 빌드에만 있는 필드는 플레이어에게는 없는 필드입니다.

없는 필드는 조용히 무시됩니다. 필드가 숫자일 때는 괜찮습니다. 오래된 베이스에서는 여러분의 동물이 그냥 보통 음량으로 짖을 뿐입니다. 필드가 차단일 때는 괜찮지 않습니다. 절대 싸우면 안 되는 고양이가 태연히 싸우게 되니까요. 즉 숫자는 낮아져도 되지만 차단은 안 됩니다. 여러분의 동물이 차단에 의존한다면 그것을 도입한 API로 가드하고, 그보다 오래된 것에서는 애드온이 통째로 비활성으로 남게 두세요.

3. 시작하기 전에 필요한 것

스킨이 입혀진 모델. 여러분의 동물에는 media/models_X/Skinned/ 아래에 자기 .glb가 필요하고, 그 파일은 21개의 Rac_* 클립 전부를 담고 있어야 합니다. 클립은 모델 파일끼리 상속되지 않습니다. 클립이 열다섯 개인 모델은, 나머지 여섯 개 중 하나를 요구받는 첫 순간에 얼어붙는 동물이 됩니다. 모델은 또한 뼈 60개 미만이어야 하고 최상위 노드가 항등이어야 합니다. 아니면 엔진이 프레임마다 예외를 던지고 동물은 검은 얼룩으로 그려집니다.

아직 모델이 없어도, CD.applyDogModel을 베이스의 몸 중 하나로 가리키면 나머지는 전부 쓰고 시험할 수 있습니다. 동물은 카라멜루처럼 보이겠지만, 이 설명서의 모든 시스템은 돌아갑니다.

몸에 쓸 텍스처, 그리고 견사 창에 쓸 초상화.

코드를 쓰기 전에 내릴 결정 하나: 여러분의 동물은 품종입니까, 종입니까? 품종은 숫자가 다른 개입니다. 종은 몇몇 일거리를 아예 가지고 있지 않은 동물입니다. 이 차이는 겉모습이 아니라 어떤 필드를 쓰는지를 바꾸며, 7절이 그 이야기입니다.

4. 애드온의 파일 구성

이것이 공개된 애드온 중 가장 작은 CD: Pug의, 중요한 부분만 추린 모습입니다.

CompanionDogsPug/

      scripts/models_pug.txt

그리고 mod.info:

id=CompanionDogsPug
name=CD: Pug
description=Pugs for Companion Dogs. REQUIRES the Companion Dogs mod (0.6.8 or newer).
poster=poster.png
icon=icon.png
require=CompanionDogs
modversion=0.1.0
pzversion=42.19.0
versionMin=42.18.0

require=CompanionDogs가 핵심 줄입니다. 이 줄은 베이스의 Lua가 전부 여러분 것보다 먼저 실행되도록 각 단계에서 보장합니다. shared가 먼저, 그다음 client, 그다음 server입니다. 이것이 없으면 여러분의 파일이 먼저 로드될 수 있고, 그러면 모든 CD. 호출이 nil 인덱싱이 됩니다.

versionMin으로는 "Companion Dogs 0.6.8이 필요함"을 말할 수 없습니다. 그 필드는 게임 빌드의 관문이고 그 이상은 아닙니다. 의존 모드의 버전을 적는 mod.info 필드는 존재하지 않습니다. 베이스의 하한은 다음 절의 가드가 강제하고, 플레이어에게는 설명문으로 알립니다. 거기에 말로 적으세요. 적지 않으면 플레이어가 받는 유일한 증상은 끝내 나타나지 않는 동물입니다.

5. 버전 가드

애드온의 모든 Lua 파일 맨 위에, 여러분의 애드온이 실제로 필요로 하는 숫자로 이것을 넣으세요.

local CD = CompanionDogs
if not (CD and CD.registerBreed and (CD.API_VERSION or 0) >= 3) then return end

베이스가 없거나 너무 오래되었다면 파일은 두 번째 줄에서 되돌아갑니다. 그러면 애드온은 아무것도 하지 않습니다. 품종도, 스폰도, 무들도 없고, 로그에 한 줄도 남지 않습니다. 이 침묵은 의도된 것입니다. 절반만 로드되는 애드온은 아예 로드되지 않는 애드온보다 나쁩니다. 플레이어에게 이름은 있는데 행동은 없는 동물이 남기 때문입니다.

가드는 파일 단위이고, 각 파일은 자기가 쓰는 것을 가드합니다. PugDefinitions.lua는 모델 헬퍼가 필요하므로 그쪽을 가드합니다.

if not (CompanionDogs and CompanionDogs.applyDogModel and CompanionDogs.DOG_SOUNDS) then return end

전역을 직접 만들지 마세요. 애드온 안의 CompanionDogs = CompanionDogs or {}는 없는 베이스를 반쯤 지어진 테이블로 바꿔 버리고, 그 아래의 모든 가드가 통과하면 안 될 때 통과합니다. 전역은 읽기만 하고 절대 쓰지 마세요.

6. 품종 등록하기

shared 파일에서 호출 하나면 됩니다.

CD.registerBreed({
    key = "pug",
    engineBreed = "pug",
    typePrefix = "pug",
    nameKey = "IGUI_PD_Breed_pug",
    litter = { 1, 2 },
    xpMult = { scent = 1.5, combat = 1, obedience = 2.0, hunt = 1.2, herding = 1.0 },
    combatPower = 0.15,
    lethalityCurve = { min = 0.40, max = 1.3 },
    canKill = false,
    canKnockdown = false,
    combatStressMult = 0.9,
    panicThreshold = 0.70,
    bagMult = 0.6,
    sentinelMult = 1.35,
    barkNoiseMult = 1.5,
    alertModeLocked = true,
    loyaltyDecayMult = 0,
    geneRange = {
        strength       = { 0.00, 0.10 },
        aggressiveness = { 0.05, 0.20 },
        resistance     = { 0.00, 0.15 },
        stress         = { 0.55, 0.85 },
    },
    spawns = {
        { id = "pughouse", class = "house", suffix = "|pg", breed = "pug",
          chance = function() return CD.strayChancePerHouse() / CD.PUG_HOUSE_RARITY end },
    },
})

이 호출이 품종을 등록하고, 그 품종의 동물 타입 셋을 등록하고, 여러분의 동물이 교배에 들어가도록 번식 순서를 다시 만들고, 스폰 단계를 등록합니다.

잘못된 정의는 예외를 던지지 않고 nil을 돌려주므로, 실수가 로드 전체를 끌고 내려가는 일은 없습니다. 모든 거절은 이름이 붙은 한 줄을 출력하니, 품종을 처음 등록할 때는 로그를 읽으세요.

필수 필드

필드 무엇인가
key 여러분 품종의 식별자. 모든 모드를 통틀어 유일. 출시 후에는 절대 바꾸지 않습니다.
typePrefix 동물 타입 셋의 접두사. <접두사>pup, <접두사>female, <접두사>male. 몸의 메시를 고릅니다.
nameKey 표시 이름의 번역 키.
xpMult 기술별 학습 속도. scent, combat, obedience, hunt, herding. 1.0이 보통입니다.
combatPower 얼마나 세게 때리는지. 카라멜루는 0.20, 싸우는 품종은 1.0을 넘습니다.
lethalityCurve { min, max }. 전투 0에서 전투 10까지 피해가 어떻게 자라는지.
geneRange 네 유전자의 출생 범위. strength, aggressiveness, resistance, stress. 각각 0에서 1 사이의 { 하한, 상한 }입니다.

선택 필드

필드 기본값 무엇을 하는가
engineBreed key와 같음 엔진에 넘기는 품종 이름으로, 텍스처를 고릅니다. 품종마다 유일.
descKey IGUI_PD_BreedDesc_<key> 설명문의 키. 설명을 공유하는 품종들은 키 하나를 함께 가리키게 하세요.
litter 베이스 값 한 배당 강아지 { 하한, 상한 }.
canKill true false면 좀비를 깎기는 하되 마지막 일격은 절대 넣지 않습니다.
canKnockdown false true면 좀비를 넘어뜨릴 수 있습니다.
combatStressMult 1 싸움 한 번이 그 동물에게 얼마나 스트레스인지.
panicThreshold 베이스 값 싸움을 그만두는 스트레스 수준. panicImmune = true는 절대 그만두지 않음입니다.
bagMult 1 안장가방 용량 배수.
puppySize 0.6 강아지의 절대적인 시각 크기. 작은 품종은 반드시 설정해야 합니다. 안 하면 강아지가 성체 크기로 태어납니다.
sentinelMult 1 최종 보초 반경에 곱합니다.
barkNoiseMult 1 경보 짖음의 반경과 음량을 조절합니다. 소음을 키울 뿐 만들지는 않습니다. 샌드박스의 소음 옵션이 꺼져 있으면 어떤 품종도 짖어서 좀비를 끌어들이지 않습니다.
loyaltyDecayMult 1 하루치 충성도 감소에 곱합니다. 0이면 유대가 결코 옅어지지 않습니다.
alertModeLocked false 동물이 완전 경계에 고정됩니다. 주인은 어디에서도 조용히나 침묵으로 바꿀 수 없습니다. 시끄러운 경보가 곧 설계일 때 쓰세요.
huntFetchLevel 6 사냥감을 주인에게 물어오기 시작하는 사냥 레벨.
huntDeliverTimeoutMin 5 전달을 포기하기 전까지 계속 시도하는 게임 분.
distract 꺼짐 { <종류> = { chance = 0..1, ... } }. 모드 없이도, 레벨 없이도 알아서 무언가를 쫓습니다. 아래 참조.
idleAnimMs 베이스 값 대기 애니메이션 창의 길이, 밀리초. 클립이 개의 것보다 짧을 때 설정하세요. 안 하면 루프가 다시 시작되어 동작 중간에 잘립니다.
restAnim true false면 대기와 경비에서 엎드리지 않고 서 있습니다.
voices 개 소리 { bark, growl, idle, wildbark, pet }. 아래 참고.
skills, canBreed, huntMaxPrey 전부 켜짐 구조적 차단. 7절.

정의에 넣은 숫자와 플래그는 CD.breedNumber(animal, 필드)와 CD.breedFlag(animal, 필드)로 다시 읽습니다. CD.getBreedDef(animal).필드를 직접 읽는 것보다 이 둘을 쓰세요. 없는 필드를 대신 처리해 주고, 베이스가 움직여도 계속 동작합니다.

본능: distract

다른 모든 필드는 동물에게 무언가를 잘하라고 요구합니다. 이것만은 주의를 기울이는 데 서투르라고 요구합니다.

distract = {
    prey = { chance = 0.25 },
},

이것을 선언한 품종은 이따금 무언가를 알아채고, 하던 일을 내던지고 쫓아갑니다. 어떤 모드도 켜지지 않은 상태에서 그렇게 하며, 대기에서도 따라오기에서도 마찬가지이고, 그동안 주도권은 당신에게 없습니다. 명령은 복종 판정이 이미 쓰고 있는 distracted 메시지와 함께 거부되어 돌아옵니다. 통하는 명령은 이리 와 하나뿐이고, 그것이 취소합니다.

보너스가 아니라 당신이 품종에게 주는 대가로 다루세요. 그것이 진행되는 동안 동물은 주인 곁에 없고 경계하지도 않습니다. 붙잡아 두기 어렵다는 것이 특징인 품종에 어울립니다. 플레이어가 의지하기를 바라는 사역견에는 어울리지 않습니다.

모든 종류는 같은 선택 항목을 받고, 빠뜨린 것은 모드의 기본값으로 떨어집니다.

필드 하는 일
chance 0..1. 해당 종류의 트리거가 실제로 무언가를 찾았을 때만 굴립니다. "25%"를 뜻하려고 25를 쓰면 로그에 이름이 적힌 줄과 함께 거부됩니다
radius 트리거가 뒤지는 타일 수. 그 종류가 탐색을 한다면
durationMin 창이 저절로 만료되기까지의 게임 분
cooldownMin 같은 동물이 다시 산만해질 수 있기까지의 게임 분

prey 종류

베이스 모드가 함께 제공하는 유일한 종류입니다. 동물은 야생 동물을 쫓고, classes가 어떤 것이 주의를 끄는지 고릅니다.

distract = {
    prey = { chance = 0.25, radius = 6, classes = { tiny = true, small = true } },
},

무엇을 선언하든 두 가지 한계는 그대로입니다.

  • 당신의 huntMaxPrey를 결코 넘지 않습니다. 여기에는 사냥 시스템과 같은 깔때기가 적용되므로, 상한이 small인 품종은 large를 선언해도 사슴을 쫓지 않습니다.
  • 레벨 관문은 tiny에서만 건너뜁니다. 설치류는 사냥 0의 갓 길들인 동물도 잡습니다. 쥐 잡기는 누구도 훈련해서 얻는 기술이 아니기 때문입니다. small을 선언하면 당신의 품종은 모든 것을 내던지고 토끼를 쫓아가지만, 실제로 죽이려면 래브라도에게 필요한 것과 같은 사냥 레벨이 여전히 필요합니다. 본능은 무엇이 주의를 끄는지 정하고, 훈련은 무엇을 쓰러뜨릴 수 있는지를 계속 정합니다. 이 두 번째 한계가 없으면 classes는 사냥 사다리를 지워버리는 지름길이 됩니다.

샌드박스의 사냥 토글은 여전히 마무리를 결정하지, 추격을 결정하지 않습니다. 사냥을 꺼도 동물은 달리지만 사냥감은 달아납니다.

이렇게 잡은 사냥감은 일반 회수 절차를 그대로 거칩니다. 즉, 사체를 주인에게 물고 갈지 쓰러진 자리에 둘지는 품종의 huntFetchLevel이 결정합니다. 0으로 두면 동물은 첫날부터 가져다주며, 고양이가 죽은 쥐를 물어다 주는 것이 바로 이 때문입니다. 회수는 산만함의 창이 닫힌 뒤에도 계속됩니다. 사냥감이 죽는 순간 동물은 다시 명령을 받아들이고, 돌아오는 길은 그 품종 자신의 huntDeliverTimeoutMin으로 돌아갑니다. huntFetchLevel을 건드리지 않으면 기본값 6이 적용되므로, 품종은 본능으로 쫓아가되 물어 오는 권리는 따로 얻어야 합니다.

자신만의 종류 작성하기

distract는 디스패처이고, prey는 그저 함께 제공되는 종류일 뿐입니다. 자신의 것을 등록하세요.

CD.registerDistraction("butterfly", {
    gate  = function(animal, cfg) return animal:isOutside() end,   -- optional, cheap pre-check
    find  = function(animal, cfg) return findButterflyNear(animal, cfg.radius) end,
    drive = function(animal, owner, d, cfg) return chaseIt(animal, d) end,
    stop  = function(animal, d) end,                               -- optional, cleanup
})

그런 다음 다른 종류와 똑같이 품종에 선언합니다: distract = { butterfly = { chance = 0.10 } }

gate는 모드의 전역 스캔 예산보다 먼저 돌고, 값싼 거부가 있을 자리입니다. find는 예산 뒤에 돌고, 비용은 거기 있습니다. drive는 아직 동물을 이끄는 동안 true를, 끝났을 때 false를 돌려주며 그것이 창을 닫습니다. 당신의 핸들러는 자체 pcall 안에서 돕니다. 예외를 던지면 모드는 로그에 이름이 적힌 줄을 쓰고, 그 종류를 이번 세션 동안 등록 해제하며, 동반자의 나머지는 계속 작동하게 둡니다.

앞으로의 베이스 종류를 위해 예약된, 아직 구현되지 않은 이름: drink, eat, play. 오늘 그 이름으로 종류를 등록할 수는 있지만, 베이스가 자기 것을 내놓는 날 그 이름은 베이스의 것이 됩니다.

목소리

종이 다르면 같은 말을 하지 않습니다. voices가 없으면 여러분의 고양이는 짖습니다.

CD.registerVoices({
    CDCatMeow = "bark", CDCatGrowl = "bark", CDCatPurr = "bark",
    CDCatPet = "fx", CDCatMeowAmbient = "ambient",
})
voices = { bark = "CDCatMeow", growl = "CDCatGrowl", idle = "CDCatPurr",
           wildbark = "CDCatMeowAmbient", pet = "CDCatPet" },

CD.registerVoices는 있어도 그만인 장식이 아닙니다. 이것이 없으면 소리는 나긴 하지만 플레이어의 카테고리 슬라이더와 게임의 효과음 볼륨을 무시합니다. 무엇도 고장 나 보이지 않기 때문에 아무도 신고하지 않는 종류의 결함입니다. voices에서 빠뜨린 키는 개 소리로 되돌아갑니다. 개 품종에서는 그게 원하는 바지만, 다른 종에서는 결코 원하는 바가 아닙니다.

7. 시스템 하나를 통째로 끄기

다섯 가지 기술은 다섯 가지 시스템과 하나씩 대응합니다.

기술 그것이 곧 어떤 시스템인가
scent 보초. 좀비를 알아채고 여러분에게 알리는 일
combat 싸움, 경비 모드, 자기방어
obedience 재주 트리
hunt 사냥, 그리고 주인에게 주는 채집 보너스
herding 우리 안 가축 돌보기

종은 숫자가 나쁜 개가 아닙니다. 그 일거리들 중 몇 가지를 아예 갖지 않은 동물입니다. 그래서 갖지 않은 것을 선언합니다.

skills = { combat = false, herding = false },
canBreed = false,
huntMaxPrey = "tiny",

없거나 true면 그 동물은 해당 기술을 가진 것이므로, 없애는 것만 적으면 됩니다.

기술 하나를 끄면 세 가지가 한꺼번에 일어납니다. 시스템이 아예 돌지 않고, 그 기술은 경험치를 결코 얻지 않으며, 막대와 그 명령이 인터페이스에서 사라집니다. 셋이 함께입니다. 막대만 숨기면 아무도 못 보는 곳에서 기술이 자라고, 시스템만 막으면 막대가 영원히 0에 박혀 있게 됩니다.

canBreed = false가 테이블 밖에 있는 이유는 번식에는 막대도 경험치도 없기 때문입니다. 그리고 전면적입니다. 그 동물은 임신하지 않고, 짝으로 선택되지 않으며, 같은 품종끼리도 번식하지 않습니다. 정상적으로 번식하되 개와는 절대 교배하지 않는 동물을 원한다면, 그것은 이것이 아니라 아래의 species입니다.

종

개가 아니라 다른 동물을 추가하는 애드온은 이렇게 선언합니다.

CD.registerSpecies({ key = "cat",
                     nounKey  = "IGUI_PD_SpeciesNoun_cat",
                     youngKey = "IGUI_PD_Young_cat" })

CD.registerBreed({ ..., species = "cat" })

이 필드는 지금까지 공개된 모든 품종에 없으며, 없으면 "dog"로 간주됩니다. 따라서 이미 작성한 것의 동작은 아무것도 바뀌지 않습니다.

이 필드는 두 가지 일을 합니다. 번식이 종 단위로 닫힙니다. 명령에서든, 시간당 수동 굴림에서든, 디버그 도구에서든 똑같이, 한 쌍은 양쪽이 같은 종일 때만 임신합니다. 그리고 인터페이스가 당신의 동물을 개라고 부르지 않게 됩니다. nounKey는 "이 %1은(는) 이미 다른 생존자의 것입니다" 같은 문장을 채우는 맨 명사이고, youngKey는 당신 종의 새끼가 창과 맥락 메뉴와 견사에서 달고 다니는 이름표로, 개라면 그 자리에 강아지가 들어갑니다.

species를 등록하지 않고 선언해도 치명적이지는 않습니다. 관문이 원본 문자열을 비교하므로 동물은 여전히 자기 종 밖의 번식을 거부합니다. 개의 것으로 떨어지는 것은 두 명사뿐이고, 로그가 그것을 이름으로 알려줍니다. 이 대체가 한쪽으로만 작동하는 것은 의도적입니다. 반대로 등록되지 않은 종을 개로 취급하면 당신의 동물이 조용히 개와 번식하게 되기 때문입니다.

이것은 차단이므로 degrade되지 않습니다. API 6보다 오래된 베이스에서는 이 필드가 조용히 무시되고, 번식에 관한 한 당신의 동물은 개입니다. 개와 절대 교배해서는 안 된다면 API 6을 확인하거나, 베이스가 오래된 동안에는 canBreed = false를 유지하세요. 고양이가 하는 것이 그것입니다.

huntMaxPrey는 존재하는 사냥 안에서의 상한이며, hunt = false와는 다른 것입니다. "tiny"(생쥐, 쥐, 다람쥐), "small"(토끼, 너구리), "large"(사슴. 기본값이며 상한 없음)를 받습니다. 상한보다 큰 사냥감은 여러분의 동물에게 보이지 않습니다. 쫓지도 않고 가리키지도 않습니다. 이 단계에서 벗어난 값은 "large"로 떨어지고 로그에 이름 붙은 한 줄을 남깁니다.

차단된 동물에게 비활성 버튼이 생기지는 않습니다. 해당 항목이 방사형 메뉴, 상황 메뉴, 창에서 사라지고, 서버 쪽 거절은 조용합니다. 명령을 무시했다는 표시가 뜬다면 거짓말입니다. 이것은 불복종이 아니니까요. 설계는 품종 설명문에서 설명하세요. 이 필드들이 새 번역 키를 데려오지 않는 이유가 그것입니다.

8. 동물 정의

엔진은 메시를 품종이 아니라 동물 타입에 묶습니다. 그래서 여러분의 품종에는 자기 타입 셋이 필요합니다. 여기가 애드온의 기계적인 부분이고, 가장 짧은 길은 기존 애드온의 파일을 복사해 이름을 바꾸는 것입니다.

Definitions/animal/ 아래 shared 파일에 들어가는 세 조각입니다.

AnimalDefinitions.stages["pug"] = {}
AnimalDefinitions.stages["pug"].stages = {}
AnimalDefinitions.stages["pug"].stages["pugpup"] = {}
AnimalDefinitions.stages["pug"].stages["pugpup"].ageToGrow = 3 * 30
AnimalDefinitions.stages["pug"].stages["pugpup"].nextStage = "pugfemale"
AnimalDefinitions.stages["pug"].stages["pugpup"].nextStageMale = "pugmale"
AnimalDefinitions.breeds["pug"].breeds["pug"].texture = "Pug"
AnimalDefinitions.breeds["pug"].breeds["pug"].textureMale = "Pug"
AnimalDefinitions.breeds["pug"].breeds["pug"].rottenTexture = "Raccoon_Rotting"
AnimalDefinitions.breeds["pug"].breeds["pug"].invIconMale = "CDDogPaw_64"
AnimalDefinitions.breeds["pug"].breeds["pug"].invIconMaleDead = "CDDogPawDead_64"
local pugfemale = {}
CD.applyDogModel(pugfemale, "Pug_Body")
CD.applyDogBehaviour(pugfemale)
pugfemale.female = true
pugfemale.babyType = "pugpup"
pugfemale.minSize = 1.5
pugfemale.maxSize = 2.0
pugfemale.minWeight = 5
pugfemale.maxWeight = 8
pugfemale.wildFleeTimeUntilDeadTimer = CD.STRAY_NO_BLEEDOUT
pugfemale.breeds = AnimalDefinitions.breeds["pug"].breeds
pugfemale.stages = AnimalDefinitions.stages["pug"].stages
pugfemale.genes = AnimalDefinitions.genome["dog"].genes
AnimalDefinitions.animals["pugfemale"] = pugfemale

베이스가 주는 헬퍼:

헬퍼 무엇을 채우는가
CD.applyDogModel(t, "Body_Model") 몸 모델, 스켈레톤, 도축 텍스처, 애님셋
CD.applyDogBehaviour(t) 동반자에게 필요한 엔진 쪽 동작 플래그 전부
CD.applyDogAvatar(t) 동물 창의 초상화 카메라
CD.DOG_SOUNDS 발소리와 효과음의 공유 테이블
CD.STRAY_NO_BLEEDOUT 겁먹은 유기견이 과다출혈로 죽지 않게 하는 값
CD.defineDogParts(typePrefix, engineBreed) 세 성장 단계 전부의 도축 부위

뻔하지 않은 규칙이 넷 있습니다.

애님셋은 "raccoon"으로 남아야 합니다. CD.applyDogModel이 설정합니다. 갈라낸 애님셋은 자기 상태 기계를 불러오지 못하고, 상태 기계가 없는 동물은 그 자리에 얼어붙은 동물입니다.

게놈은 재사용하세요: AnimalDefinitions.genome["dog"].genes. 직접 쓰지 마세요.

mate는 절대 선언하지 마세요. 이것이 있으면 엔진은 어떤 동물 구역 안에서든 자기 고유의 교미를 돌립니다. 그 교미는 모드의 번식 차단도 샌드박스 옵션도 무시하고, 유대 없는 새끼를 낳습니다. 베이스가 안전망으로 부팅 때 이 필드를 지우지만, 거기에 기대지는 마세요.

부위는 필수입니다. 전용 파일에 세 줄.

if CompanionDogs and CompanionDogs.defineDogParts then
    CompanionDogs.defineDogParts("pug", "pug")
end

이것이 없으면 여러분의 동물을 도축할 때 바닐라 코드가 죽습니다. 부위 정의를 타입과 품종으로 찾다가 nil을 밟기 때문입니다.

작은 동물은 초상화 카메라를 손봐야 합니다. CD.applyDogAvatar의 초상화 줌은 개에 맞춰 보정되어 있고, 아바타 줌은 배율입니다. 동물이 작을수록 숫자가 커집니다. 개 대비 크기 비율로 줌을 나누고 오프셋에는 같은 비율을 곱하세요. 안 그러면 여러분의 동물은 자기 초상화 아래쪽에 아주 작게 앉아 있게 됩니다.

9. 모델 스크립트

media/scripts/ 아래의 파일 하나가, 여러분의 모델이 존재한다는 것을 게임에 알립니다.

module Base
{
    model Pug_Body
    {
        mesh = Skinned/Pug_Body,
        shader = animalEffect,
        static = false,
        animationsMesh = PugAnim,
        attachment head
        {
            offset = -0.0061 0.1671 0.0507,
            rotate = -179.0 -5.0 95.0,
            bone = Dummy01,
        }
    }

    animationsMesh PugAnim
    {
        meshFile = Skinned/Pug_Body,
        keepMeshAnimations = true,
    }
}

keepMeshAnimations = true가 모델 파일 안의 클립을 쓸 수 있는 상태로 유지합니다. 이것이 없으면 모델은 로드되지만 결코 움직이지 않습니다.

head 어태치먼트는 모자 같은 것이 얹히는 자리입니다. 안장가방을 여러분의 동물에 맞추고 싶다면 saddlebags_l, saddlebags_r, saddlebags_c를 같은 방식으로 척추 뼈에 더하세요. 이 숫자들은 게임 안에서 동물을 보면서 조금씩 밀어 찾는 것이지, 모델을 재서 얻는 것이 아닙니다. 수학적으로 한가운데인 가방도 털 있는 몸 위에서는 여전히 비뚤어져 보입니다.

10. 동물이 나타나는 곳

유기 동물은 그 청크가 처음 로드될 때 건물마다, 청크마다 추첨됩니다. 추첨은 단계의 목록으로 적습니다. 품종 정의 안의 spawns에 넣거나, CD.registerStraySpawns(목록)으로 넘깁니다.

spawns = {
    { id = "pughouse", class = "house", suffix = "|pg", breed = "pug", indoor = 85,
      chance = function() return CD.strayChancePerHouse() / CD.PUG_HOUSE_RARITY end },
    { id = "pugpetvet", class = "petvet", suffix = "|pv", breed = "pug",
      chance = function() return CD.PUG_PETVET_CHANCE * CD.dogSpawnMultiplier() end },
},
키 무엇인가
id 단계의 이름. 여러분 자신의 로그용입니다
class 추첨이 이루어지는 건물 클래스
chance 백분율을 돌려주는 함수. 숫자가 아니라 함수인 이유는 샌드박스 배수를 실시간으로 따라가기 위해서입니다.
suffix 영구 저장소의 키. 생태계 전체에서 유일하고, 절대 바뀌지 않습니다.
breed 나타나게 할 품종 키
gate 참거짓을 돌려주는 선택적 함수. 추첨 전에 확인합니다. 허스키가 CD.isWinter를 씁니다.
indoor 길거리 대신 건물 안에서 태어날 백분율. 기본값 35.

확률에는 CD.dogSpawnMultiplier()를 곱하거나, CD.strayChancePerHouse()를 여러분만의 희귀도로 나누세요. 어느 쪽이든 플레이어의 샌드박스 설정이 계속 작동합니다. 맨 숫자를 적으면 작동하지 않습니다.

indoor는 선호이지 약속이 아닙니다. 그 청크에서 빈 실내 타일이 없는 건물은 바깥 타일로 되돌아갑니다.

건물 클래스

베이스가 넷을 등록해 두었고, 그대로 쓸 수 있습니다.

클래스 무엇에 맞는가
house 상점이 아닌 주거 건물
police 경찰서와 그 비슷한 것
petvet 애완동물 가게와 동물병원
farm 농장 건물. 도시 밖에서도 허용됩니다

어느 것도 맞지 않으면 직접 등록하세요.

CD.registerBuildingClass("mineshaft", function(def) return def:isX() end,
                         { skipUrbanGate = true })

일치 함수는 건물 정의를 받아 보호된 호출 안에서 돕니다. 그러니 그 안의 실수가 청크 로딩을 끌고 내려가지 않습니다. skipUrbanGate는 도시가 아닌 청크에서도 클래스가 추첨되게 합니다. 농장이나 숲속 오두막에 필요한 설정입니다. exclusive는 건드리지 마세요. 베이스 클래스들끼리는 배타적이지만, 애드온 클래스는 그 위에 겹쳐 맞는 가산적인 것으로 만들어졌습니다.

이미 쓰이는 접미사

접미사는 "이 건물은 이미 추첨됨"이 저장되는 키의 일부입니다. 같은 접미사를 쓰는 두 모드는 서로의 추첨을 망가뜨립니다.

접미사는 모두 세로 막대로 시작합니다. 다음은 이미 사용 중입니다.

  • 베이스: 빈 접미사, 그리고 g, h, hv, bc
  • 로트와일러: rw, r
  • 도베르만: db, dm
  • 래브라도: lb, lk
  • 퍼그: pg, pv
  • 고양이: ct, cv, ctw, cvw, cto, cvo, ctc, cvc, ctx, cvx

아무도 쓰지 않는 것을 고르고, 그다음에는 다시는 손대지 마세요.

11. 품종 무들

무들은 client 파일입니다. CD.DogMoodles에 테이블을 덧붙이면 베이스가 그리고, 추적하고, 정리합니다.

CD.DogMoodles[#CD.DogMoodles + 1] = {
    id = "shadow",
    breed = "pug",
    nameKey = "IGUI_PD_Moodle_Shadow",
    descKey = "IGUI_PD_Moodle_Shadow_desc",
    icon = "CD_Moodle_Shadow",
    fg = "CD_MoodShadowFG",
    tintR = 0.92, tintG = 0.52, tintB = 0.68,
    condition = function(player, dog)
        if not dog or dog:isDead() then return 0 end
        if CD.getBreed(dog) ~= "pug" then return 0 end
        if CD.isDisloyal(dog) then return 0 end
        return 1
    end,
    apply = function(player, dog, elapsedMin)
        CD.relieveMood(player, CD.moodleReliefPerMin() * elapsedMin)
    end,
}

condition은 단계를 돌려주고, "표시 안 함"이면 0을 돌려줍니다. apply에는 마지막 호출 이후의 게임 분이 넘어오므로, 고정된 틱을 가정하지 말고 효과에 elapsedMin을 곱하세요.

아이콘은 32에서 128 픽셀까지 여섯 가지 크기로 함께 배포하세요. 인터페이스가 플레이어의 배율에 따라 크기를 고르므로, 빠진 크기는 빈 네모가 됩니다.

직접 만든 무들은 오버레이로 그려집니다. 게임 자체의 무들 시스템은 모드가 넣는 새 항목을 받아 주지 않기 때문입니다. 그 부분은 이미 처리되어 있지만, 무들이 바닐라 것들 사이가 아니라 모드 자체의 띠에 나타나는 이유가 그것입니다.

12. 훅

베이스가 서버에서 호출하는 함수 목록이 둘 있습니다. shared 파일에서 덧붙이세요. 각 핸들러는 자기만의 보호된 호출 안에서 돌기 때문에, 망가진 애드온이 베이스를 끌고 내려갈 수 없습니다.

CD.onHuntDelivered, API 2부터. 동물이 사냥감을 주인 발치에 내려놓은 직후에 호출됩니다.

CD.onHuntDelivered[#CD.onHuntDelivered + 1] = function(animal, owner)
    -- server side, so this is the right place to write mod data
end

CD.onUpkeepStress, API 3부터. 유지 관리 주기마다, 베이스가 채워지지 않은 욕구에서 오는 스트레스를 더한 뒤 기록하기 전에 호출됩니다. 숫자를 돌려주면 합계에 더해집니다.

CD.onUpkeepStress[#CD.onUpkeepStress + 1] = function(animal, needsStress)
    return CD.pugHeatRatio(animal) * CD.PUG_HEAT_STRESS_MAX
end

애드온이 동물의 지속적인 스트레스에 영향을 줄 수 있는 유일한 방법입니다. 유지 관리는 매 주기마다 값을 다시 계산해 덮어쓰므로, 바깥에서 쓴 것은 다음 틱에 사라집니다. 더위, 추위, 비처럼 환경에서 오는 상태를 다루기에 알맞은 도구입니다.

멀티플레이 규칙을 한 줄로. 클라이언트는 절대 모드 데이터를 쓰지 않는다. 클라이언트 쪽 쓰기는 다음 동기화에서 서버의 사본을 덮어 버리고, 증상은 몇 분 뒤 전혀 다른 곳에서 나타납니다. 작업은 서버 파일에서 하거나, 이미 그쪽에서 도는 이 훅들 안에서 하세요.

13. 번역 키

media/lua/shared/Translate/<LANG>/ 아래, 언어 폴더마다 IG_UI.json을 하나씩 넣으세요. 베이스는 열넷을 넣습니다. EN, PTBR, CH, CN, DE, ES, FR, IT, JP, KO, RU, TH, UA, VI.

품종에 필요한 키:

키 어디에 나오는가
IGUI_PD_Breed_<key> 품종 이름. 모드 인터페이스 전반에
IGUI_PD_BreedDesc_<key> 동물 카드에 적히는 설명
IGUI_Breed_<engineBreed> 게임 자체 화면에서의 품종 이름
IGUI_AnimalType_<type> 여러분의 세 타입마다 하나씩
종 키들 종을 추가했다면 CD.registerSpecies에 넘긴 nounKey와 youngKey
무들 키들 무들이 있다면 그 이름과 설명 
{
    "IGUI_Breed_pug": "Pug",
    "IGUI_AnimalType_pugmale": "Pug (male)",
    "IGUI_AnimalType_pugfemale": "Pug (female)",
    "IGUI_AnimalType_pugpup": "Pug (puppy)",
    "IGUI_PD_Breed_pug": "Pug",
    "IGUI_PD_BreedDesc_pug": "The house dog: the first companion whose worth is not fighting."
}

물릴 만한 것이 둘 있습니다. 번역 문자열 안의 그대로의 퍼센트 기호는 그것을 보여 주는 화면을 죽입니다. 서식기가 자리표시자로 읽기 때문입니다. 그리고 바이트 순서 표식이 붙은 언어 파일은 컴파일되지 않으며, 그 오류는 정작 망가진 파일이 아닌 다른 파일의 이름을 댑니다.

14. 세이브가 기억하는 것

여러분의 식별자 중 셋은 세이브 파일에 기록되고 이후로 계속 다시 읽힙니다.

  • key. 여러분의 동물 하나하나에 저장되는 품종 식별자
  • typePrefix. 엔진이 저장하는 동물 타입을 이루는 것
  • suffix. "이미 추첨됨" 저장소의 키. 스폰 단계마다 하나

셋 다 출시 후에는 결코 이름을 바꿀 수 없습니다. key를 바꾸면 그 품종의 살아 있는 동물이 전부 고아가 됩니다. suffix를 바꾸면 기존 모든 세이브의 모든 건물이 다시 추첨되고, 몇 달을 플레이한 세계가 갑자기 여러분의 동물로 가득 찹니다.

그 재추첨이 쓸모 있는 유일한 경우는 그것이 바로 목적일 때입니다. CD: Cats는 새 털색 넷에 일부러 새 접미사를 주었습니다. 이미 돌아가던 세계에도 그것들이 나타나기 시작하게 하려는 것이었고, 반면 원래의 검은 고양이는 역사적인 접미사를 지켜 재추첨하지 않았습니다.

그 품종의 동물이 살아 있는 세이브에서 애드온을 빼면 그 동물을 잃습니다. 엔진은 더 이상 알지 못하는 타입의 동물을 버립니다. 베이스는 죽지 않고 유대와 견사도 깔끔하게 낮아지지만, 동물은 사라집니다. 공개된 모든 애드온이 그러하듯, 워크샵 페이지에 그렇게 적으세요.

알 수 없는 품종은 실패하지 않고 낮아집니다. 여러분의 애드온이 없으면 베이스는 무엇을 묻든 기본 품종으로 되돌리므로, 여러분의 모드 없이 연 세이브도 읽을 수 있습니다.

15. 공개하기 전에

  • 가드가 모든 Lua 파일에 있고, 실제로 쓰는 API를 적고 있다.
  • 베이스 버전의 하한이 설명문에 말로 적혀 있다. versionMin으로는 그것을 말할 수 없다.
  • 첫 로드에서 로그를 읽었다. 그러지 않으면 CD.registerBreed는 조용히 거절하고, 모든 거절이 이름 붙은 한 줄을 남긴다.
  • CD.defineDogParts를 호출하고 있다. 자기 동물을 한 마리 도축해 죽지 않는지 확인한다.
  • key, typePrefix, 스폰 접미사가 유일하고, 앞으로도 계속 그것으로 만족한다.
  • 작은 품종은 puppySize를 설정했고, 강아지를 직접 보고 확인했다.
  • 다른 종이라면 CD.registerVoices를 호출하고 voices를 채웠다. 아니면 짖는다.
  • 무들 아이콘이 여섯 크기 전부 있다.
  • 함께 배포하는 모든 언어 폴더에 모든 키가 있다. 빠진 키는 화면에 날것의 키를 보여 준다.
  • 싱글플레이만이 아니라 멀티플레이에서 시험했다. 위치, 소유, 모드 데이터는 그쪽에서 다르게 움직인다.
  • 워크샵 페이지가 살아 있는 동물이 있는 세이브에서 애드온을 빼지 말라고 경고한다.

16. 흔한 실수

"내 동물이 도무지 나타나지 않아요." 거의 언제나 가드입니다. 여러분의 애드온이 설치된 베이스에 없는 API를 요구하고 있어서, 의도대로 비활성 상태입니다. 자기 API 번호를 2절의 표와 맞춰 보세요.

"나타나긴 하는데 얼어 있어요." 애님셋이 "raccoon"이 아니거나, 모델에 클립이 빠졌습니다. 둘 다 영원히 가만히 서 있는 동물로 나옵니다.

"검은 얼룩으로 그려지고 로그가 넘칩니다." 모델의 뼈가 60개를 넘습니다.

"도축하면 죽습니다." CD.defineDogParts를 호출하지 않았습니다.

"강아지가 성체 크기로 태어납니다." puppySize를 설정하지 않은 작은 품종입니다. 이 값은 절대값이고 매 스윕마다 다시 적용되므로, 타입 자체의 크기 범위로는 구제되지 않습니다.

"내 품종 둘이 자꾸 서로 바뀝니다." engineBreed를 공유하고 있습니다. 접두사는 메시를 고르는 것이라 한 가족이 공유할 수 있지만, engineBreed는 텍스처를 고르며 그 가족 안에서 승부를 가르는 것이므로 품종마다 유일해야 합니다.

"소리는 나는데 볼륨 조절을 무시합니다." 그 소리에 대해 CD.registerVoices를 호출하지 않았습니다.

"싱글에서는 되는데 서버에서 이상하게 굽니다." 무언가가 클라이언트에서 모드 데이터를 쓰고 있습니다. 서버로 옮기세요.

"전투를 껐는데 좀비와 싸웠어요." 돌아가고 있는 베이스가 API 5보다 오래되어, 거기에는 그 필드가 아직 없었고 조용히 무시되었습니다. 가드가 낮추지 말고 막아야 하는 경우가 바로 이것입니다.
