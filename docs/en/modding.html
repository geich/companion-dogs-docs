Companion Dogs: Modding Manual

How to build your own add-on: a new breed, or a whole new species, as a separate Workshop mod that plugs into Companion Dogs.

This manual is for people who write mods. If you only want to play, the other two manuals are the ones you want: Features for what the dog does, and Breeds for the breeds themselves.

It assumes you can already read Lua and that you have a rigged, animated model for your animal. The art pipeline is not covered here; section 3 lists what the model file has to satisfy, and no more.

This is a public contract. Everything named in this manual is meant to be called from outside the mod. Anything not named here is internal and can change in any release without notice.

1. What an add-on is

An add-on is a normal Workshop mod that declares require=CompanionDogs and calls one function at load time. It adds one breed (or several, if they share a body), and nothing else. Everything that makes the animal behave like a companion already lives in the base mod and is shared.

The base owns:

  • the animation state machine, the animation set and the skeleton
  • following, pathing, combat, hunting, herding, the sentinel, needs and upkeep
  • the whole user interface: the dog window, the radial, the context menu, the kennel, the map marker
  • taming, bonding, breeding, puppies and crossbreeds
  • the sandbox options, and the multiplayer replication

Your add-on owns:

  • the numbers that make your animal different from a Caramelo
  • its body model, its texture, its portrait and, if it has one, its moodle icon
  • where it is found in the world
  • its name and description, in every language you ship

That split is the whole point. A breed pack is a few hundred lines of Lua, because the hard part is already running.

One breed, one look. A breed is a set of numbers plus one appearance. If you want two colours of the same animal to behave differently, those are two breeds. If you want two colours that behave the same, they are still two breeds to the base (two names, two entries in the kennel), and you write them from one shared table, the way CD: Cats does with its five coats.

2. The API versions

CD.API_VERSION is a plain number. It has only ever grown by adding things, so an add-on written against an older version keeps loading on a newer base without a single change.

API Base version What it added
1 0.6.3 CD.registerBreed, the spawn registry, breed moodles
2 0.6.6 huntFetchLevel, huntDeliverTimeoutMin, the CD.onHuntDelivered hook
3 0.6.8 sentinelMult, barkNoiseMult, loyaltyDecayMult, the CD.onUpkeepStress hook
4 0.6.9 alertModeLocked
5 0.7.0 skills, canBreed, huntMaxPrey, descKey, voices, CD.registerVoices
6 0.7.1 species, CD.registerSpecies

The number to guard on is the lowest API that your add-on actually needs, and the base version in that table is the one you name on your Workshop page. Take it from that table and not from whatever the base happened to be while you were writing: a field that exists only in the developer build is a field your players do not have.

A missing field is ignored in silence. That is fine when the field is a number: on an older base your animal simply barks at the normal volume. It is not fine when the field is a block, because then a cat that must never fight will happily fight. So: numbers can degrade, blocks cannot. If your animal depends on a block, guard on the API that introduced it and let the add-on stay inert on anything older.

3. What you need before you start

A skinned model. Your animal needs its own .glb under media/models_X/Skinned/, and that file has to carry the complete set of 21 Rac_* animation clips. Clips are not inherited between model files: a model with fifteen clips gives you an animal that freezes the first time it is asked to do one of the other six. The model also has to stay under 60 bones and have its top node at identity, or the engine throws once per frame and the animal renders as a black smear.

If you do not have a model yet, you can still write and test everything else by pointing CD.applyDogModel at one of the base bodies. The animal will look like a Caramelo, but every system in this manual will run.

A texture for the body, and a portrait for the kennel window.

One decision, before any code: is your animal a breed or a species? A breed is a dog with different numbers. A species is an animal that does not have some of the jobs at all. The difference is not cosmetic, it changes which fields you write, and section 7 is about it.

4. The files of an add-on

This is CD: Pug, the smallest published add-on, with the parts that matter:

CompanionDogsPug/
  42/
    mod.info
    icon.png
    poster.png
    media/
      models_X/Skinned/Pug_Body.glb
      scripts/models_pug.txt
      textures/Body/Pug.png
      textures/CDPortrait_pug.png
      lua/shared/CompanionDogsPug_Breed.lua
      lua/shared/Definitions/animal/PugDefinitions.lua
      lua/shared/Definitions/animal/CompanionDogsPug_Parts.lua
      lua/client/CompanionDogsPug_Moodle.lua
      lua/shared/Translate/EN/IG_UI.json
      lua/shared/Translate/PTBR/IG_UI.json
  common/

And the mod.info:

id=CompanionDogsPug
name=CD: Pug
description=Pugs for Companion Dogs. REQUIRES the Companion Dogs mod (0.6.8 or newer).
poster=poster.png
icon=icon.png
require=CompanionDogs
modversion=0.1.0
pzversion=42.19.0
versionMin=42.18.0

require=CompanionDogs is the important line. It guarantees that all of the base Lua has run before any of yours, in every phase: shared first, then client, then server. Without it your files can load first and every CD. call is a nil index.

versionMin cannot express "needs Companion Dogs 0.6.8". That field is the game build gate and nothing else, and there is no mod.info field for a dependency version. The floor on the base is enforced by the guard in the next section, and announced to players in your description. Write it there, in words, or the only symptom a player gets is an animal that never appears.

5. The version guard

Put this at the top of every Lua file of your add-on, with the number your add-on actually needs:

local CD = CompanionDogs
if not (CD and CD.registerBreed and (CD.API_VERSION or 0) >= 3) then return end

With the base missing or too old, the file returns at line two. The add-on then does nothing at all: no breed, no spawn, no moodle, not one line in the log. That silence is deliberate. An add-on that half loads is worse than one that does not load, because the player gets an animal with a name and no behaviour.

The guard is per file, and each file guards on what it uses. PugDefinitions.lua needs the model helpers, so it guards on those instead:

if not (CompanionDogs and CompanionDogs.applyDogModel and CompanionDogs.DOG_SOUNDS) then return end

Never create the global. CompanionDogs = CompanionDogs or {} in an add-on turns a missing base into a half built table and every guard downstream passes when it should not. Read the global, never write it.

6. Registering the breed

One call, in a shared file:

CD.registerBreed({
    key = "pug",
    engineBreed = "pug",
    typePrefix = "pug",
    nameKey = "IGUI_PD_Breed_pug",
    litter = { 1, 2 },
    xpMult = { scent = 1.5, combat = 1, obedience = 2.0, hunt = 1.2, herding = 1.0 },
    combatPower = 0.15,
    lethalityCurve = { min = 0.40, max = 1.3 },
    canKill = false,
    canKnockdown = false,
    combatStressMult = 0.9,
    panicThreshold = 0.70,
    bagMult = 0.6,
    sentinelMult = 1.35,
    barkNoiseMult = 1.5,
    alertModeLocked = true,
    loyaltyDecayMult = 0,
    geneRange = {
        strength       = { 0.00, 0.10 },
        aggressiveness = { 0.05, 0.20 },
        resistance     = { 0.00, 0.15 },
        stress         = { 0.55, 0.85 },
    },
    spawns = {
        { id = "pughouse", class = "house", suffix = "|pg", breed = "pug",
          chance = function() return CD.strayChancePerHouse() / CD.PUG_HOUSE_RARITY end },
    },
})

That call inserts the breed, registers its three animal types, rebuilds the breeding order so your animal takes part in crossbreeding, and registers the spawn steps.

A bad definition returns nil instead of throwing, so a mistake never takes the load down with it. Every rejection prints a named line, so read the log the first time you register a breed.

Required fields

Field What it is
key your breed identifier, unique across every mod. Never changed after release.
typePrefix prefix of the three animal types: <prefix>pup, <prefix>female, <prefix>male. Chooses the body mesh.
nameKey translation key of the display name.
xpMult learning speed per skill: scent, combat, obedience, hunt, herding. 1.0 is normal.
combatPower how hard it hits. The Caramelo is 0.20, a fighting breed is above 1.0.
lethalityCurve { min, max }, how the damage grows from Combat 0 to Combat 10.
geneRange birth range of the four genes: strength, aggressiveness, resistance, stress. Each is { low, high } inside 0 to 1.

Optional fields

Field Default What it does
engineBreed the key breed name given to the engine, which chooses the texture. Unique per breed.
descKey IGUI_PD_BreedDesc_<key> description key. Point several breeds at one key when they share a description.
litter base value { min, max } puppies per birth.
canKill true false means it wears zombies down but never lands the killing blow.
canKnockdown false true lets it knock a zombie over.
combatStressMult 1 how much a fight costs it in stress.
panicThreshold base value stress level at which it stops fighting. panicImmune = true means never.
bagMult 1 saddlebag capacity multiplier.
puppySize 0.6 absolute visual scale of the puppy. A small breed must set this, otherwise the puppy is born adult sized.
sentinelMult 1 multiplies the final sentinel radius.
barkNoiseMult 1 scales the radius and volume of the alarm bark. It scales noise, it does not create it: with the sandbox noise option off, no breed attracts zombies with a bark.
loyaltyDecayMult 1 multiplies the daily loyalty decay. 0 means the bond never fades.
alertModeLocked false the animal is stuck on full alert: the owner cannot set quiet or silent, anywhere. Use it when the loud alarm is the design.
huntFetchLevel 6 Hunt level from which it carries the kill back to its owner.
huntDeliverTimeoutMin 5 game minutes it will keep trying to deliver before giving up.
distract off { <kind> = { chance = 0..1, ... } }. The breed goes after things on its own, no mode and no level required. See below.
idleAnimMs base value length of the idle animation window, in milliseconds. Set it when your clips are shorter than the dog ones, or the loop restarts and gets cut mid gesture.
restAnim true false keeps the animal standing on Stay and Guard instead of lying down.
voices dog sounds { bark, growl, idle, wildbark, pet }. See below.
species "dog" which species the animal belongs to. Breeding is closed per species. Section 7.
skills, canBreed, huntMaxPrey everything on the structural blocks. Section 7.

Numbers and flags you add to the definition can be read back with CD.breedNumber(animal, field) and CD.breedFlag(animal, field). Prefer those two to reading CD.getBreedDef(animal).field yourself: they handle the missing field for you, and they keep working when the base moves.

Instinct: distract

Every other field asks the animal to be good at something. This one asks it to be bad at paying attention.

distract = {
    prey = { chance = 0.25 },
},

A breed that declares it will, every so often, notice something and go after it, dropping whatever it was doing. It does this with no mode switched on, from Stay as well as Follow, and you are not in charge while it lasts: orders come back refused with the distracted message the obedience roll already uses. The one command that gets through is Come, which cancels it.

Treat it as a cost you are giving your breed, not a bonus. While it runs, the animal is not at the owner's side and is not keeping watch. It fits a breed whose defining trait is being hard to hold on to. It does not fit a working dog you want the player to rely on.

Every kind takes the same optional knobs, and anything you leave out falls back to the mod's defaults:

Field What it does
chance 0..1, rolled only when the kind's trigger actually found something. Writing 25 for "25%" is rejected with a named line in the log
radius tiles the trigger searches, when the kind searches at all
durationMin game minutes the window lasts before it expires on its own
cooldownMin game minutes before the same animal can be distracted again

The prey kind

The only kind the base mod ships. The animal goes after wild animals, and classes picks which ones get its attention:

distract = {
    prey = { chance = 0.25, radius = 6, classes = { tiny = true, small = true } },
},

Two limits hold no matter what you declare:

  • It never reaches above your huntMaxPrey. The same funnel the hunting system uses applies here, so a breed capped at small will not chase deer even if it declares large.
  • The level gate is only skipped for tiny. Rodents get caught by a freshly tamed animal with Hunt 0, because catching mice is not a skill anything trains for. Declare small and your breed will drop everything and run after the rabbit, but to actually kill it, it still needs the same Hunt level the Labrador needs. Instinct decides what gets its attention; training still decides what it can bring down. Without that second limit, classes would be a shortcut that erases the Hunting ladder.

The sandbox Hunting toggle still owns the kill, not the chase: with hunting off the animal still runs, but the prey gets away.

A kill made this way goes through the normal retrieval, so your breed's huntFetchLevel decides whether it carries the body back to the owner or leaves it where it fell. Set it to 0 and the animal delivers from day one, which is what makes a cat bring you a dead rat. The delivery outlives the distraction window: once the prey is dead the animal takes orders again, and the trip home runs on its own huntDeliverTimeoutMin. Leave huntFetchLevel alone and the default of 6 applies, so the breed chases on instinct and still has to earn the right to fetch.

Writing your own kind

distract is a dispatcher, and prey is just the kind that ships with it. Register your own:

CD.registerDistraction("butterfly", {
    gate  = function(animal, cfg) return animal:isOutside() end,   -- optional, cheap pre-check
    find  = function(animal, cfg) return findButterflyNear(animal, cfg.radius) end,
    drive = function(animal, owner, d, cfg) return chaseIt(animal, d) end,
    stop  = function(animal, d) end,                               -- optional, cleanup
})

Then declare it on the breed like any other kind: distract = { butterfly = { chance = 0.10 } }.

gate runs before the mod's global scan budget and is where cheap rejections belong. find runs after the budget and is where the cost lives. drive returns true while it is still driving the animal, and false when it is done, which closes the window. Your handler runs in its own pcall: if it throws, the mod logs a named line, unregisters that kind for the session and leaves the rest of the companion working.

Names reserved for future base kinds, not implemented yet: drink, eat, play. You can register a kind under one of those names today, but the base will win the name when it ships its own.

The voice

A different species does not speak the same language. Without voices, your cat barks:

CD.registerVoices({
    CDCatMeow = "bark", CDCatGrowl = "bark", CDCatPurr = "bark",
    CDCatPet = "fx", CDCatMeowAmbient = "ambient",
})
voices = { bark = "CDCatMeow", growl = "CDCatGrowl", idle = "CDCatPurr",
           wildbark = "CDCatMeowAmbient", pet = "CDCatPet" },

CD.registerVoices is not optional decoration. Without it the sounds still play, but they ignore the player's category slider and the game's effect volume, which is a failure nobody reports because nothing looks broken. A key you leave out of voices falls back to the dog sound, which is what you want for a breed of dog and never what you want for another species.

7. Turning a whole system off

The five skills are the five systems, one for one:

Skill The system it is
scent the sentinel: noticing zombies and warning you
combat fighting, the Guard mode and self defence
obedience the trick tree
hunt hunting, plus the foraging bonus it gives its owner
herding tending livestock in a pen

A species is not a dog with worse numbers. It is an animal that does not have some of those jobs at all. So it declares what it does not have:

skills = { combat = false, herding = false },
canBreed = false,
huntMaxPrey = "tiny",

Absent or true means the animal has that skill, so you only write the ones you are removing.

Turning a skill off does three things at once: the system never runs, the skill never earns experience, and the bar and its commands disappear from the interface. All three, together. Hiding only the bar would leave the skill growing where nobody can see it; blocking only the system would leave a bar stuck at zero forever.

canBreed = false is separate from the table because breeding has no bar and no experience. It is total: the animal does not conceive, is never picked as a partner, and does not breed with its own kind either. If what you actually want is an animal that breeds normally but never with a dog, that is species, below, not this.

The species

An add-on that adds another animal, rather than another dog, declares it:

CD.registerSpecies({ key = "cat",
                     nounKey  = "IGUI_PD_SpeciesNoun_cat",
                     youngKey = "IGUI_PD_Young_cat" })

CD.registerBreed({ ..., species = "cat" })

The field is absent on every breed published so far, and absent means "dog". So nothing you already wrote changes behaviour.

It does two things. Breeding is closed per species: a pair only conceives when both sides are the same species, in the command, in the passive hourly roll and in the debug tool alike. And the interface stops calling your animal a dog: nounKey is the bare noun that fills sentences like "This %1 already belongs to another survivor", and youngKey is the label the young of your species carries in the window, the context menu and the kennel, where a dog says Puppy.

Declaring species without registering it is not fatal: your animal still refuses to breed outside its own species, because the gate compares the raw string. Only the two nouns fall back to the dog's, and the log says so by name. The fallback is deliberately one-sided, because the opposite, treating an unregistered species as a dog, would quietly let your animal breed with dogs.

This is a block, so it does not degrade. On a base older than API 6 the field is ignored in silence and your animal is a dog for breeding purposes. If it must never cross with one, guard on API 6, or keep canBreed = false while the base is older, which is what the cat does.

huntMaxPrey is a ceiling inside a hunt that exists, which is a different thing from hunt = false. It takes "tiny" (mice, rats, squirrels), "small" (rabbits, raccoons) or "large" (deer, the default, no ceiling). Prey above the ceiling is invisible to your animal: it does not chase it and does not even point at it. A value outside that ladder falls back to "large" and prints a named line in the log.

A blocked animal does not get a disabled button. The option leaves the radial, the context menu and the window, and the refusal on the server is silent. A halo saying the order was ignored would be a lie, because this is not disobedience. Explain the design in your breed description instead. That is why none of these fields brings a new translation key with it.

8. The animal definitions

The engine binds the mesh to the animal type, not to the breed, so your breed needs its own three types. This is the mechanical part of an add-on, and the shortest path is to copy the file of an existing add-on and rename it.

The three pieces, in one shared file under Definitions/animal/:

AnimalDefinitions.stages["pug"] = {}
AnimalDefinitions.stages["pug"].stages = {}
AnimalDefinitions.stages["pug"].stages["pugpup"] = {}
AnimalDefinitions.stages["pug"].stages["pugpup"].ageToGrow = 3 * 30
AnimalDefinitions.stages["pug"].stages["pugpup"].nextStage = "pugfemale"
AnimalDefinitions.stages["pug"].stages["pugpup"].nextStageMale = "pugmale"
AnimalDefinitions.breeds["pug"].breeds["pug"].texture = "Pug"
AnimalDefinitions.breeds["pug"].breeds["pug"].textureMale = "Pug"
AnimalDefinitions.breeds["pug"].breeds["pug"].rottenTexture = "Raccoon_Rotting"
AnimalDefinitions.breeds["pug"].breeds["pug"].invIconMale = "CDDogPaw_64"
AnimalDefinitions.breeds["pug"].breeds["pug"].invIconMaleDead = "CDDogPawDead_64"
local pugfemale = {}
CD.applyDogModel(pugfemale, "Pug_Body")
CD.applyDogBehaviour(pugfemale)
pugfemale.female = true
pugfemale.babyType = "pugpup"
pugfemale.minSize = 1.5
pugfemale.maxSize = 2.0
pugfemale.minWeight = 5
pugfemale.maxWeight = 8
pugfemale.wildFleeTimeUntilDeadTimer = CD.STRAY_NO_BLEEDOUT
pugfemale.breeds = AnimalDefinitions.breeds["pug"].breeds
pugfemale.stages = AnimalDefinitions.stages["pug"].stages
pugfemale.genes = AnimalDefinitions.genome["dog"].genes
AnimalDefinitions.animals["pugfemale"] = pugfemale

The helpers the base gives you:

Helper What it fills in
CD.applyDogModel(t, "Body_Model") body model, skeleton, butchered textures and the animation set
CD.applyDogBehaviour(t) every engine behaviour flag a companion needs
CD.applyDogAvatar(t) the portrait camera for the animal window
CD.DOG_SOUNDS the shared footstep and foley table
CD.STRAY_NO_BLEEDOUT the value that stops a frightened stray from bleeding to death
CD.defineDogParts(typePrefix, engineBreed) the butchering parts of all three stages

Four rules that are not obvious:

The animation set has to stay "raccoon". CD.applyDogModel sets it. A forked animation set does not load its state machine, and an animal without a state machine is an animal frozen in place.

Reuse the genome: AnimalDefinitions.genome["dog"].genes. Do not write your own.

Never declare mate. With it, the engine runs its own native mating inside any animal zone, which ignores the mod's breeding block and its sandbox options, and produces puppies with no bond. The base clears the field at boot as a safety net, but do not rely on that.

Parts are mandatory. Three lines in their own file:

if CompanionDogs and CompanionDogs.defineDogParts then
    CompanionDogs.defineDogParts("pug", "pug")
end

Without them, butchering your animal crashes the vanilla code, because it indexes the parts definition by type and breed and walks into a nil.

Small animals need their avatar camera adjusted. The portrait zoom in CD.applyDogAvatar is calibrated for a dog, and avatar zoom is magnification: the smaller the animal, the bigger the number. Divide the zoom by the size ratio against a dog and multiply the offsets by it, or your animal sits tiny at the bottom of its own portrait.

9. The model script

One file under media/scripts/, which is what tells the game your model exists:

module Base
{
    model Pug_Body
    {
        mesh = Skinned/Pug_Body,
        shader = animalEffect,
        static = false,
        animationsMesh = PugAnim,
        attachment head
        {
            offset = -0.0061 0.1671 0.0507,
            rotate = -179.0 -5.0 95.0,
            bone = Dummy01,
        }
    }

    animationsMesh PugAnim
    {
        meshFile = Skinned/Pug_Body,
        keepMeshAnimations = true,
    }
}

keepMeshAnimations = true is what keeps the clips inside your model file usable. Without it the model loads and never animates.

The head attachment is where hats and the like sit. If you want the saddlebag to fit your animal, add saddlebags_l, saddlebags_r and saddlebags_c the same way, on the spine bone. Those numbers are found by looking at the animal in game and nudging them, not by measuring the model: a bag that is mathematically centred still looks wrong on a body with fur.

10. Where the animal spawns

Strays are rolled per building, per chunk, the first time that chunk loads. You describe your rolls as a list of steps, either inside the breed definition as spawns, or with CD.registerStraySpawns(list).

spawns = {
    { id = "pughouse", class = "house", suffix = "|pg", breed = "pug", indoor = 85,
      chance = function() return CD.strayChancePerHouse() / CD.PUG_HOUSE_RARITY end },
    { id = "pugpetvet", class = "petvet", suffix = "|pv", breed = "pug",
      chance = function() return CD.PUG_PETVET_CHANCE * CD.dogSpawnMultiplier() end },
},
Key What it is
id name of the step, for your own logs
class the building class it rolls on
chance a function returning a percentage. A function, not a number, so it can follow the sandbox multiplier live.
suffix key of the persistent store. Unique in the whole ecosystem, and never changed.
breed the breed key to spawn
gate optional function returning a boolean, checked before the roll. The Husky uses CD.isWinter.
indoor percentage chance of being born inside the building instead of the street. Default 35.

Multiply your chance by CD.dogSpawnMultiplier(), or divide CD.strayChancePerHouse() by a rarity of your own. Either way the player's sandbox setting keeps working, which it will not if you write a bare number.

indoor is a preference and not a promise: a building with no free interior tile in that chunk falls back to a tile outside.

The building classes

The base registers four, and you can use them directly:

Class Matches
house residential buildings that are not shops
police police stations and the like
petvet pet shops and veterinary clinics
farm farm buildings, and it is allowed outside town

If none of them fits, register your own:

CD.registerBuildingClass("mineshaft", function(def) return def:isX() end,
                         { skipUrbanGate = true })

The match function receives the building definition and runs inside a protected call, so a mistake in it cannot take the chunk load down. skipUrbanGate lets the class roll in a chunk that is not urban, which is what a farm or a forest cabin needs. Leave exclusive alone: the base classes are exclusive between themselves, and an add-on class is meant to be additive, matching on top of them.

Suffixes already taken

The suffix is part of the key under which "this building was already rolled" is saved. Two mods using the same suffix corrupt each other's rolls.

Every suffix starts with a vertical bar. These are already in use:

  • Base: the empty suffix, and g, h, hv, bc
  • Rottweiler: rw, r
  • Doberman: db, dm
  • Labrador: lb, lk
  • Pug: pg, pv
  • Cats: ct, cv, ctw, cvw, cto, cvo, ctc, cvc, ctx, cvx

Pick something nobody else is using, then never touch it again.

11. The breed moodle

A moodle is a client file. You append a table to CD.DogMoodles, and the base draws it, tracks it and cleans it up:

CD.DogMoodles[#CD.DogMoodles + 1] = {
    id = "shadow",
    breed = "pug",
    nameKey = "IGUI_PD_Moodle_Shadow",
    descKey = "IGUI_PD_Moodle_Shadow_desc",
    icon = "CD_Moodle_Shadow",
    fg = "CD_MoodShadowFG",
    tintR = 0.92, tintG = 0.52, tintB = 0.68,
    condition = function(player, dog)
        if not dog or dog:isDead() then return 0 end
        if CD.getBreed(dog) ~= "pug" then return 0 end
        if CD.isDisloyal(dog) then return 0 end
        return 1
    end,
    apply = function(player, dog, elapsedMin)
        CD.relieveMood(player, CD.moodleReliefPerMin() * elapsedMin)
    end,
}

condition returns the level, or 0 for "not showing". apply is called with the game minutes since the last call, so multiply your effect by elapsedMin instead of assuming a fixed tick.

Ship the icon in six sizes, from 32 to 128 pixels. The interface picks the size by the player's scaling, and a missing size is an empty square.

Custom moodles are drawn as an overlay, not through the game's own moodle system, which does not accept new entries from a mod. That is handled for you, but it is why the moodle appears in the mod's own strip and not among the vanilla ones.

12. Hooks

Two lists of functions the base calls on the server. Append to them from a shared file. Each handler runs inside its own protected call, so a broken add-on cannot take the base down with it.

CD.onHuntDelivered, from API 2, called right after the animal drops a kill at its owner's feet:

CD.onHuntDelivered[#CD.onHuntDelivered + 1] = function(animal, owner)
    -- server side, so this is the right place to write mod data
end

CD.onUpkeepStress, from API 3, called every upkeep cycle, after the base has added the stress from unmet needs and before it is written. Return a number, which is added to the total:

CD.onUpkeepStress[#CD.onUpkeepStress + 1] = function(animal, needsStress)
    return CD.pugHeatRatio(animal) * CD.PUG_HEAT_STRESS_MAX
end

This is the only way an add-on can influence the animal's continuous stress. Upkeep recomputes and overwrites the value every cycle, so anything you write from outside is lost on the next tick. It is the right tool for a condition that comes from the environment: heat, cold, rain.

The multiplayer rule, in one line: the client never writes mod data. A client side write clobbers the server's copy on the next sync, and the symptom shows up minutes later somewhere unrelated. Do the work in a server file, or in one of these hooks, which already run there.

13. Translation keys

Ship one IG_UI.json per language folder, under media/lua/shared/Translate/<LANG>/. The base ships fourteen: EN, PTBR, CH, CN, DE, ES, FR, IT, JP, KO, RU, TH, UA, VI.

The keys a breed needs:

Key Where it shows
IGUI_PD_Breed_<key> the breed name, everywhere in the mod's interface
IGUI_PD_BreedDesc_<key> the description on the animal's card
IGUI_Breed_<engineBreed> the breed name in the game's own screens
IGUI_AnimalType_<type> one for each of your three types
your species keys the nounKey and youngKey you passed to CD.registerSpecies, if you added a species
your moodle keys name and description, if you have a moodle 
{
    "IGUI_Breed_pug": "Pug",
    "IGUI_AnimalType_pugmale": "Pug (male)",
    "IGUI_AnimalType_pugfemale": "Pug (female)",
    "IGUI_AnimalType_pugpup": "Pug (puppy)",
    "IGUI_PD_Breed_pug": "Pug",
    "IGUI_PD_BreedDesc_pug": "The house dog: the first companion whose worth is not fighting."
}

Two things that will bite you. A literal percent sign in a translated string crashes the screen that shows it, because the formatter reads it as a placeholder. And a language file with a byte order mark does not compile, with an error that names a different file than the broken one.

14. What the save remembers

Three of your identifiers are written into save files and read back forever:

  • key, the breed identifier stored on every animal of yours
  • typePrefix, which forms the animal types the engine stores
  • suffix, the key of the "already rolled" store, one per spawn step

None of the three can ever be renamed after release. Renaming a key orphans every living animal of that breed. Renaming a suffix makes every building in every existing save roll again, and a world that had been played for months suddenly fills with your animal.

The one time that re-roll is useful is when it is the point: CD: Cats gave its four new coats new suffixes on purpose, precisely so that they would start appearing in worlds that were already running, while the original black cat kept its historic suffix and did not re-roll.

Removing an add-on from a save that has living animals of that breed loses them. The engine discards an animal whose type it no longer knows. The base does not crash, the bond and the kennel degrade cleanly, but the animal is gone. Say so on your Workshop page, the way every published add-on does.

An unknown breed degrades instead of failing. If your add-on is missing, the base falls back to the default breed for anything it is asked about, so a save opened without your mod is readable.

15. Before you publish

  • The guard is on every Lua file, and names the API you actually use.
  • The base version floor is written in your description, in words. versionMin cannot say it.
  • You read the log on first load. CD.registerBreed rejects in silence otherwise, and every rejection prints a named line.
  • CD.defineDogParts is called. Butcher one of your animals and see that it does not crash.
  • Your key, typePrefix and spawn suffixes are unique, and you are happy with them forever.
  • A small breed sets puppySize, and you have seen a puppy to prove it.
  • If it is another species, CD.registerVoices is called and voices is filled in, or it barks.
  • The moodle icon exists in all six sizes.
  • Every language folder you ship has every key. A missing key shows the raw key on screen.
  • You tested in multiplayer, not only in single player. Position, ownership and mod data all behave differently there.
  • Your Workshop page warns against removing the add-on from a save with living animals.

16. Common mistakes

"My animal never appears." Almost always the guard: your add-on needs an API the installed base does not have, so it is inert on purpose. Check your API number against the table in section 2.

"It appears, but it is frozen." The animation set is not "raccoon", or your model is missing clips. Both come out as an animal that stands still forever.

"It renders as a black smear and the log floods." More than 60 bones in the model.

"Butchering it crashes." CD.defineDogParts was not called.

"The puppy is born the size of an adult." A small breed that did not set puppySize. The value is absolute and is re-applied on every sweep, so the type's own size range does not save you.

"Two of my breeds keep turning into each other." They share an engineBreed. The prefix chooses the mesh and can be shared by a family; engineBreed chooses the texture and is what breaks the tie inside that family, so it has to be unique per breed.

"The sound plays but ignores the volume slider." CD.registerVoices was not called for that sound.

"It works in single player and misbehaves on a server." Something is writing mod data on the client. Move it to the server.

"It fought a zombie even though I turned combat off." The base it is running on is older than API 5, where the field did not exist yet and was ignored in silence. This is exactly the case where the guard has to block instead of degrade.

Something in this manual wrong, or missing? Say so on Discord.
