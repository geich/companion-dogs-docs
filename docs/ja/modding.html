Companion Dogs: Mod制作マニュアル

自分のアドオンの作り方。新しい犬種、あるいは種族まるごとを、Companion Dogs に噛み合う別の Workshop Mod として作ります。

このマニュアルは Mod を書く人向けです。遊ぶだけなら、必要なのは他の二冊のほうです。犬が何をするかは 機能、犬種そのものは 犬種 を見てください。

Lua が読めること、そして自分の動物のリグ付き・アニメーション付きモデルを持っていることを前提にして います。アート側のパイプラインはここには書きません。第 3 節がモデルファイルの満たすべき条件を挙げ ますが、それ以上には踏み込みません。

これは公開された契約です。 このマニュアルが名前を挙げているものは、すべて Mod の外から呼ばれ るためにあります。ここに名前がないものは内部のもので、どのバージョンでも予告なく変わり得ます。

1. アドオンとは何か

アドオンは、require=CompanionDogs を宣言し、ロード時に関数をひとつ呼ぶだけの、ごく普通の Workshop Mod です。追加するのは犬種ひとつ（体を共有するなら複数）だけで、それ以外は何もしません。動物が 仲間らしく振る舞うために必要なものは、すでにベース Mod の中にあり、共有されています。

ベースが持っているもの:

  • アニメーションのステートマシン、animset、スケルトン
  • 追従、パス探索、戦闘、狩り、家畜の世話、見張り、欲求、メンテナンス
  • インターフェース一式。犬のウィンドウ、ラジアル、コンテキストメニュー、犬舎、マップの目印
  • 手なずけ、絆、繁殖、子犬、雑種
  • サンドボックス設定と、マルチプレイの同期

あなたのアドオンが持つもの:

  • あなたの動物をカラメロと違うものにする数値
  • 体のモデル、テクスチャ、肖像、そして moodle があればそのアイコン
  • 世界のどこで見つかるか
  • 名前と説明文を、同梱するすべての言語で

この分担がすべての要点です。犬種パックは数百行の Lua で済みます。難しいところはもう動いているから です。

ひとつの犬種にひとつの見た目。 犬種とは、数値の組と見た目ひとつのことです。同じ動物の二色に 違う振る舞いをさせたいなら、それは二つの犬種です。同じ振る舞いの二色が欲しい場合でも、ベースから 見ればやはり二つの犬種であり（名前が二つ、犬舎の項目も二つ）、CD: Cats が五つの毛色でやっているよう に、共有テーブルから書き起こします。

2. API のバージョン

CD.API_VERSION はただの数値です。これまで追加だけで大きくなってきたので、古いバージョンに向けて 書かれたアドオンは、新しいベースでも一行も変えずにロードされ続けます。

API ベースのバージョン 追加されたもの
1 0.6.3 CD.registerBreed、スポーンのレジストリ、犬種 moodle
2 0.6.6 huntFetchLevel、huntDeliverTimeoutMin、フック CD.onHuntDelivered
3 0.6.8 sentinelMult、barkNoiseMult、loyaltyDecayMult、フック CD.onUpkeepStress
4 0.6.9 alertModeLocked
5 0.7.0 skills、canBreed、huntMaxPrey、descKey、voices、CD.registerVoices
6 0.7.1 species、CD.registerSpecies

ガードに書く数値は、あなたのアドオンが実際に必要とする一番低い API です。そしてその表にある ベースのバージョンが、Workshop のページに書くべき数字です。書いていたときにベースがたまたま何だった かではなく、この表から取ってください。開発ビルドにしかないフィールドは、プレイヤーが持っていない フィールドです。

ないフィールドは黙って無視されます。 それはフィールドが数値なら問題ありません。古いベースでは、 あなたの動物はただ普通の音量で吠えるだけです。フィールドが「禁止」の場合は問題です。決して戦っては いけない猫が、平気で戦い始めてしまいます。つまり、数値は劣化してよく、禁止は劣化してはいけません。 あなたの動物が禁止に依存しているなら、それを導入した API でガードし、それより古いものではアドオン ごと不活性のままにしてください。

3. 始める前に必要なもの

スキン済みのモデル。 あなたの動物には media/models_X/Skinned/ に置く固有の .glb が必要で、 そのファイルは 21 個の Rac_* クリップを完全に持っていなければなりません。クリップはモデル ファイル間で受け継がれません。クリップが十五個しかないモデルは、残り六個のどれかを要求された最初の 瞬間に固まる動物になります。モデルはさらに 60 ボーン未満であり、最上位ノードが単位行列でなけれ ばなりません。そうでないとエンジンが毎フレーム例外を投げ、動物は黒い滲みとして描かれます。

まだモデルがなくても、CD.applyDogModel をベースの体のどれかに向ければ、それ以外はすべて書いて 試せます。動物はカラメロの見た目になりますが、このマニュアルのすべてのシステムは動きます。

体のテクスチャと、犬舎ウィンドウ用の肖像。

コードを書く前に決めること: あなたの動物は*犬種*ですか、それとも*種族*ですか。犬種は数値の違う 犬です。種族は、いくつかの仕事をそもそも持っていない動物です。この違いは見た目の話ではなく、書く フィールドが変わります。第 7 節がその話です。

4. アドオンのファイル構成

これは公開済みで最も小さいアドオン CD: Pug の、重要な部分だけです。

CompanionDogsPug/
  42/
    mod.info
    icon.png
    poster.png
    media/
      models_X/Skinned/Pug_Body.glb
      scripts/models_pug.txt
      textures/Body/Pug.png
      textures/CDPortrait_pug.png
      lua/shared/CompanionDogsPug_Breed.lua
      lua/shared/Definitions/animal/PugDefinitions.lua
      lua/shared/Definitions/animal/CompanionDogsPug_Parts.lua
      lua/client/CompanionDogsPug_Moodle.lua
      lua/shared/Translate/EN/IG_UI.json
      lua/shared/Translate/PTBR/IG_UI.json
  common/

そして mod.info:

id=CompanionDogsPug
name=CD: Pug
description=Pugs for Companion Dogs. REQUIRES the Companion Dogs mod (0.6.8 or newer).
poster=poster.png
icon=icon.png
require=CompanionDogs
modversion=0.1.0
pzversion=42.19.0
versionMin=42.18.0

require=CompanionDogs が肝心な行です。これがあると、ベースの Lua がすべてあなたのものより先に 実行されることが、各フェーズで保証されます。まず shared、次に client、最後に server の順です。これが ないと、あなたのファイルが先にロードされることがあり、そうなると CD. の呼び出しはすべて nil への インデックスになります。

versionMin では「Companion Dogs 0.6.8 が必要」と言えません。 あのフィールドは*ゲーム*本体の バージョンのゲートであり、それ以外の何物でもありません。依存 Mod のバージョンを書く mod.info の フィールドは存在しません。ベース側の下限は次節のガードが強制し、プレイヤーには説明文で伝えます。 そこに言葉で書いてください。書かなければ、プレイヤーが受け取る唯一の症状は「動物が一向に現れない」 です。

5. バージョンガード

これをアドオンのすべての Lua ファイルの先頭に、あなたのアドオンが実際に必要とする数値で置きます。

local CD = CompanionDogs
if not (CD and CD.registerBreed and (CD.API_VERSION or 0) >= 3) then return end

ベースが無い、あるいは古すぎる場合、ファイルは二行目で戻ります。アドオンはそのとき何もしません。 犬種もスポーンも moodle もなく、ログに一行も出ません。この沈黙は意図的なものです。半分だけロード されるアドオンは、まったくロードされないアドオンより悪い。名前はあるのに振る舞いのない動物が、 プレイヤーの手元に残るからです。

ガードはファイル単位で、各ファイルは自分が使うものをガードします。PugDefinitions.lua はモデルの ヘルパーを使うので、そちらをガードします。

if not (CompanionDogs and CompanionDogs.applyDogModel and CompanionDogs.DOG_SOUNDS) then return end

グローバルを自分で作らないこと。 アドオンの中の CompanionDogs = CompanionDogs or {} は、 存在しないベースを半端に組み上がったテーブルに変えてしまい、以降のガードが通ってはいけない場面で 通ります。グローバルは読むだけにして、決して書かないでください。

6. 犬種を登録する

shared のファイルで、呼び出しはひとつだけです。

CD.registerBreed({
    key = "pug",
    engineBreed = "pug",
    typePrefix = "pug",
    nameKey = "IGUI_PD_Breed_pug",
    litter = { 1, 2 },
    xpMult = { scent = 1.5, combat = 1, obedience = 2.0, hunt = 1.2, herding = 1.0 },
    combatPower = 0.15,
    lethalityCurve = { min = 0.40, max = 1.3 },
    canKill = false,
    canKnockdown = false,
    combatStressMult = 0.9,
    panicThreshold = 0.70,
    bagMult = 0.6,
    sentinelMult = 1.35,
    barkNoiseMult = 1.5,
    alertModeLocked = true,
    loyaltyDecayMult = 0,
    geneRange = {
        strength       = { 0.00, 0.10 },
        aggressiveness = { 0.05, 0.20 },
        resistance     = { 0.00, 0.15 },
        stress         = { 0.55, 0.85 },
    },
    spawns = {
        { id = "pughouse", class = "house", suffix = "|pg", breed = "pug",
          chance = function() return CD.strayChancePerHouse() / CD.PUG_HOUSE_RARITY end },
    },
})

この呼び出しが犬種を登録し、三つの動物タイプを登録し、あなたの動物が交配に加わるように繁殖の順序を 組み直し、スポーンの手順を登録します。

不正な定義は例外を投げずに nil を返すので、間違いがロード全体を巻き込むことはありません。拒否は 必ず名前付きの一行をログに出します。だから犬種をはじめて登録するときはログを読んでください。

必須フィールド

フィールド 何であるか
key あなたの犬種の識別子。すべての Mod をまたいで一意。公開後は決して変えません。
typePrefix 三つの動物タイプの接頭辞。<接頭辞>pup、<接頭辞>female、<接頭辞>male。体のメッシュを選びます。
nameKey 表示名の翻訳キー。
xpMult スキルごとの習得速度。scent、combat、obedience、hunt、herding。1.0 が標準です。
combatPower 打撃の重さ。カラメロは 0.20、戦う犬種は 1.0 を超えます。
lethalityCurve { min, max }。戦闘 0 から戦闘 10 までダメージがどう伸びるか。
geneRange 四つの遺伝子の生まれつきの範囲。strength、aggressiveness、resistance、stress。それぞれ 0 から 1 の中の { 下限, 上限 } です。

任意フィールド

フィールド 既定値 何をするか
engineBreed key と同じ エンジンに渡す犬種名で、テクスチャを選びます。犬種ごとに一意。
descKey IGUI_PD_BreedDesc_<key> 説明文のキー。説明を共有する犬種は、まとめて一つのキーに向けます。
litter ベースの値 一回の出産あたりの子犬の { 下限, 上限 }。
canKill true false は、ゾンビを削るが決してとどめを刺さない、という意味です。
canKnockdown false true でゾンビを倒せるようになります。
combatStressMult 1 一度の戦闘がその動物にとってどれだけストレスになるか。
panicThreshold ベースの値 戦うのをやめるストレス値。panicImmune = true は「決してやめない」です。
bagMult 1 サドルバッグ容量の倍率。
puppySize 0.6 子犬の見た目の絶対スケール。小型の犬種は必ず設定してください。しないと子犬が成犬の大きさで生まれます。
sentinelMult 1 最終的な見張り半径にかかる倍率。
barkNoiseMult 1 警戒吠えの半径と音量を拡大縮小します。音を大きくするだけで、音を作りはしません。サンドボックスの騒音設定が切ってあれば、どの犬種も吠えでゾンビを引き寄せません。
loyaltyDecayMult 1 忠誠心の日々の減少にかかる倍率。0 なら絆は決して薄れません。
alertModeLocked false その動物は完全警戒に固定されます。飼い主は静かにも無音にも、どこからも変えられません。うるさい警報こそが設計であるときに使ってください。
huntFetchLevel 6 獲物を飼い主のところへ運び始める狩りのレベル。
huntDeliverTimeoutMin 5 受け渡しを諦めるまで粘るゲーム内分数。
distract オフ { <種類> = { chance = 0..1, ... } }。モードなしでも、レベルなしでも、勝手に何かを追いかけます。下記参照。
idleAnimMs ベースの値 待機アニメーションの窓の長さ、ミリ秒。あなたのクリップが犬のものより短いときに設定します。しないとループが再開して仕草の途中で切れます。
restAnim true false にすると、待機や警備のあいだ伏せずに立ったままになります。
voices 犬の音 { bark, growl, idle, wildbark, pet }。下を参照。
skills、canBreed、huntMaxPrey すべて有効 構造的な禁止。第 7 節。

定義に足した数値やフラグは、CD.breedNumber(animal, フィールド) と CD.breedFlag(animal, フィールド) で読み戻せます。CD.getBreedDef(animal).フィールド を自分で読むより、この二つを使ってください。 欠けたフィールドの扱いをやってくれますし、ベース側が動いても動き続けます。

本能：distract

ほかのフィールドはどれも、動物に何かが上手であることを求めます。これだけは、注意力が散漫であることを 求めます。

distract = {
    prey = { chance = 0.25 },
},

これを宣言したブリードは、ときどき何かに気づいて、やっていたことを放り出して追いかけます。どのモードも 入っていない状態でやり、待機からでも追従からでも同じで、その間あなたに主導権はありません。命令は服従判定が すでに使っている distracted のメッセージで拒否されて返ります。通る命令は「おいで」だけで、それが打ち切ります。

これはボーナスではなく、あなたがブリードに与えるコストとして扱ってください。走っているあいだ、動物は飼い主の そばにおらず、見張りもしません。つかまえておくのが難しいことが持ち味のブリードに合います。プレイヤーに 頼ってほしい使役犬には合いません。

どの種類も同じ任意のつまみを取り、省いたものはMOD既定値に落ちます。

フィールド 何をするか
chance 0..1。その種類のトリガーが実際に何かを見つけたときだけ振られます。「25%」のつもりで 25 と書くとログに名前付きの行を出して拒否されます
radius トリガーが探すタイル数。その種類が探索を行う場合
durationMin 窓が自然に切れるまでのゲーム内分数
cooldownMin 同じ個体がふたたび気を逸らせるまでのゲーム内分数

prey の種類

ベースMODが同梱する唯一の種類です。動物は野生動物を追いかけ、classes がどれに注意を向けるかを選びます。

distract = {
    prey = { chance = 0.25, radius = 6, classes = { tiny = true, small = true } },
},

何を宣言しても、次の二つの制限は変わりません。

  • あなたの huntMaxPrey を超えることは決してありません。ここには狩りシステムと同じ絞り込みが効くので、 上限が small のブリードは large を宣言してもシカを追いません。
  • レベルの関門が飛ばされるのは tiny だけです。げっ歯類は狩り0の飼いならしたばかりの動物でも捕まえます。 ネズミ捕りは誰も訓練して身につける技能ではないからです。small を宣言すれば、あなたのブリードはすべてを 放り出してウサギを追いますが、実際に*仕留める*には、ラブラドールに必要なのと同じ狩りレベルが依然として要ります。 本能は何に注意が向くかを決め、訓練は何を倒せるかを決め続けます。この二つ目の制限がなければ、classes は 狩りの階段を消し去る抜け道になってしまいます。

サンドボックスの狩りトグルは今も仕留めを決めるのであって、追跡を決めるのではありません。狩りをオフにしても 動物は走りますが、獲物は逃げます。

こうして仕留めた獲物は通常の回収処理を通ります。つまり、死骸を飼い主のもとへ運ぶか倒れた場所に置いていくかを 決めるのは、あなたのブリードの huntFetchLevel です。0 にすれば動物は初日から届けるようになり、これが猫が 死んだネズミを持ってくる理由です。この回収は気の逸れの時間が終わっても続きます。獲物が死んだ時点で動物は再び 命令を受け付けるようになり、帰り道はそのブリード自身の huntDeliverTimeoutMin で動きます。huntFetchLevel に触れなければ既定値の6が効くので、ブリードは本能で追いかけつつ、持ち帰る権利は自分で稼ぐことになります。

自分の種類を書く

distract はディスパッチャで、prey は同梱されている種類にすぎません。自分のものを登録してください。

CD.registerDistraction("butterfly", {
    gate  = function(animal, cfg) return animal:isOutside() end,   -- optional, cheap pre-check
    find  = function(animal, cfg) return findButterflyNear(animal, cfg.radius) end,
    drive = function(animal, owner, d, cfg) return chaseIt(animal, d) end,
    stop  = function(animal, d) end,                               -- optional, cleanup
})

あとはほかの種類と同じようにブリードで宣言します。distract = { butterfly = { chance = 0.10 } }

gate はMODのグローバルなスキャン予算より前に走り、安価な却下はここに置きます。find は予算のあとに走り、 コストはそこにあります。drive は動物をまだ導いているあいだ true を返し、終わったら false を返して窓を 閉じます。あなたのハンドラは自前の pcall の中で走ります。例外を投げた場合、MODはログに名前付きの行を書き、 その種類をそのセッションのあいだ登録解除し、相棒の残りの部分は動いたままにします。

将来のベース種類のために予約されている、まだ未実装の名前：drink、eat、play。今日これらの 名前で種類を登録することはできますが、ベースが自前のものを出す日にその名前はベースのものになります。

声

種族が違えば、同じ言葉は話しません。voices がないと、あなたの猫は吠えます。

CD.registerVoices({
    CDCatMeow = "bark", CDCatGrowl = "bark", CDCatPurr = "bark",
    CDCatPet = "fx", CDCatMeowAmbient = "ambient",
})
voices = { bark = "CDCatMeow", growl = "CDCatGrowl", idle = "CDCatPurr",
           wildbark = "CDCatMeowAmbient", pet = "CDCatPet" },

CD.registerVoices は任意の飾りではありません。これがないと音は鳴りますが、プレイヤーのカテゴリ スライダーとゲームの効果音量を無視します。何も壊れて見えないので、誰も報告してくれない類の不具合 です。voices から外したキーは犬の音に落ちます。犬の犬種ならそれで正解ですが、別の種族では決して 正解になりません。

7. システムを丸ごと切る

五つのスキルは、五つのシステムと一対一で対応します。

スキル 対応するシステム
scent 見張り。ゾンビに気づき、あなたに知らせる
combat 戦うこと、警備モード、自衛
obedience 芸のツリー
hunt 狩り、および飼い主に与える採集ボーナス
herding 囲いの中の家畜の世話

種族は、数値の悪い犬ではありません。それらの仕事のいくつかを、そもそも持たない動物です。ですから、 持っていないものを宣言します。

skills = { combat = false, herding = false },
canBreed = false,
huntMaxPrey = "tiny",

書かないか true なら、その動物はそのスキルを持っています。だから取り除くものだけを書きます。

スキルを切ると、三つのことが同時に起きます。システムが動かなくなり、そのスキルは経験値を得なく なり、バーとその指示がインターフェースから消えます。三つまとめてです。バーだけ隠せば、誰にも見えない ところでスキルが伸び続けます。システムだけ止めれば、バーが永遠にゼロで固まります。

canBreed = false がテーブルの外にあるのは、繁殖にはバーも経験値もないからです。そして全面的です。 その動物は身ごもらず、相手として選ばれず、同じ犬種とも交配しません。普通に繁殖するけれど犬とは決して交配しない動物が欲しいのなら、それはこれではなく、 下の species です。

種

犬ではなく別の動物を追加するアドオンは、こう宣言します。

CD.registerSpecies({ key = "cat",
                     nounKey  = "IGUI_PD_SpeciesNoun_cat",
                     youngKey = "IGUI_PD_Young_cat" })

CD.registerBreed({ ..., species = "cat" })

このフィールドはこれまでに公開されたどのブリードにもなく、無い場合は "dog" として扱われます。つまり、 あなたがすでに書いたものの挙動は何も変わりません。

これは2つのことをします。繁殖が種ごとに閉じます。つがいは双方が同じ種のときにだけ身ごもります。 コマンドでも、1時間ごとの受動的な抽選でも、デバッグ用ツールでも同じです。そしてUIがあなたの動物を犬と 呼ぶのをやめます。nounKey は*「この%1はすでに別の生存者のものです」のような文を埋める裸の名詞で、 youngKey はあなたの種の子が、ウィンドウ、コンテキストメニュー、犬舎で背負うラベルです。犬ならそこは 子犬*になります。

species を登録せずに宣言しても致命的ではありません。ゲートは生の文字列を比較するので、動物は自分の種 以外との交配を拒み続けます。犬のものに落ちるのは2つの名詞だけで、ログがそれを名指しで伝えます。この フォールバックが片側だけなのは意図的です。逆に、登録されていない種を犬として扱えば、あなたの動物を黙って 犬と交配させてしまうからです。

これはブロックなので、劣化しません。API 6より古いベースではこのフィールドは黙って無視され、繁殖の うえであなたの動物は犬になります。決して犬と交わってはいけないなら、API 6をチェックするか、ベースが 古いあいだは canBreed = false にしておいてください。猫がやっているのがそれです。

huntMaxPrey は存在する狩りの中での上限であり、hunt = false とは別物です。"tiny"（ネズミ、 ドブネズミ、リス）、"small"（ウサギ、アライグマ）、"large"（シカ。既定で上限なし）を取ります。 上限より大きい獲物はあなたの動物には見えません。追いませんし、指し示しもしません。この段階から外れた 値は "large" に落ち、名前付きの一行をログに出します。

禁止された動物にグレーアウトのボタンは出ません。 その項目はラジアルからもコンテキストメニュー からもウィンドウからも消え、サーバー側の拒否は無言です。「命令を無視した」と光って見せるのは嘘に なります。これは不服従ではないからです。設計は犬種の説明文で説明してください。これらのフィールドが 新しい翻訳キーを連れてこないのは、そのためです。

8. 動物定義

エンジンはメッシュを犬種ではなく動物タイプに結び付けます。ですからあなたの犬種には固有の三つの タイプが要ります。ここはアドオンの機械的な部分で、いちばんの近道は既存のアドオンのファイルをコピー して名前を変えることです。

Definitions/animal/ の shared ファイルに置く三つの部品です。

AnimalDefinitions.stages["pug"] = {}
AnimalDefinitions.stages["pug"].stages = {}
AnimalDefinitions.stages["pug"].stages["pugpup"] = {}
AnimalDefinitions.stages["pug"].stages["pugpup"].ageToGrow = 3 * 30
AnimalDefinitions.stages["pug"].stages["pugpup"].nextStage = "pugfemale"
AnimalDefinitions.stages["pug"].stages["pugpup"].nextStageMale = "pugmale"
AnimalDefinitions.breeds["pug"].breeds["pug"].texture = "Pug"
AnimalDefinitions.breeds["pug"].breeds["pug"].textureMale = "Pug"
AnimalDefinitions.breeds["pug"].breeds["pug"].rottenTexture = "Raccoon_Rotting"
AnimalDefinitions.breeds["pug"].breeds["pug"].invIconMale = "CDDogPaw_64"
AnimalDefinitions.breeds["pug"].breeds["pug"].invIconMaleDead = "CDDogPawDead_64"
local pugfemale = {}
CD.applyDogModel(pugfemale, "Pug_Body")
CD.applyDogBehaviour(pugfemale)
pugfemale.female = true
pugfemale.babyType = "pugpup"
pugfemale.minSize = 1.5
pugfemale.maxSize = 2.0
pugfemale.minWeight = 5
pugfemale.maxWeight = 8
pugfemale.wildFleeTimeUntilDeadTimer = CD.STRAY_NO_BLEEDOUT
pugfemale.breeds = AnimalDefinitions.breeds["pug"].breeds
pugfemale.stages = AnimalDefinitions.stages["pug"].stages
pugfemale.genes = AnimalDefinitions.genome["dog"].genes
AnimalDefinitions.animals["pugfemale"] = pugfemale

ベースが用意しているヘルパー:

ヘルパー 何を埋めるか
CD.applyDogModel(t, "Body_Model") 体のモデル、スケルトン、解体用テクスチャ、animset
CD.applyDogBehaviour(t) 仲間に必要なエンジン側の挙動フラグ一式
CD.applyDogAvatar(t) 動物ウィンドウの肖像カメラ
CD.DOG_SOUNDS 足音と効果音の共有テーブル
CD.STRAY_NO_BLEEDOUT 怯えた野良が出血死しないようにする値
CD.defineDogParts(typePrefix, engineBreed) 三つの成長段階すべての解体パーツ

自明でない規則が四つあります。

animset は "raccoon" のままでなければなりません。 CD.applyDogModel が設定します。フォークした animset はステートマシンを読み込まず、ステートマシンのない動物はその場で固まった動物です。

ゲノムは使い回してください: AnimalDefinitions.genome["dog"].genes。自前で書かないこと。

mate は決して宣言しないでください。 これがあるとエンジンは、動物ゾーンの中で独自のネイティブ 交配を走らせます。それは Mod の繁殖禁止もサンドボックス設定も無視し、絆のない子を産みます。ベースは 安全網として起動時にこのフィールドを消しますが、それを当てにしないでください。

パーツは必須です。 専用ファイルに三行だけ。

if CompanionDogs and CompanionDogs.defineDogParts then
    CompanionDogs.defineDogParts("pug", "pug")
end

これがないと、あなたの動物を解体したときにバニラのコードが落ちます。パーツ定義をタイプと犬種で 引きにいって nil を踏むからです。

小さい動物は肖像カメラの調整が要ります。 CD.applyDogAvatar の肖像ズームは犬に合わせて調整 されていて、アバターのズームは倍率です。動物が小さいほど数値は大きくなります。犬に対する体格比で ズームを割り、同じ比をオフセットに掛けてください。でないとあなたの動物は、自分の肖像の下の隅で 極小になります。

9. モデルスクリプト

media/scripts/ に置くファイルひとつが、あなたのモデルの存在をゲームに伝えます。

module Base
{
    model Pug_Body
    {
        mesh = Skinned/Pug_Body,
        shader = animalEffect,
        static = false,
        animationsMesh = PugAnim,
        attachment head
        {
            offset = -0.0061 0.1671 0.0507,
            rotate = -179.0 -5.0 95.0,
            bone = Dummy01,
        }
    }

    animationsMesh PugAnim
    {
        meshFile = Skinned/Pug_Body,
        keepMeshAnimations = true,
    }
}

keepMeshAnimations = true が、モデルファイルの中のクリップを使える状態に保ちます。これがないと モデルは読み込まれても決して動きません。

head のアタッチメントは帽子などが載る場所です。サドルバッグをあなたの動物に合わせたいなら、同じ やり方で saddlebags_l、saddlebags_r、saddlebags_c を背骨のボーンに足してください。これらの 数値は、ゲームの中で動物を見ながら少しずつ動かして見つけるものです。モデルを測って出すものでは ありません。数学的に中央のバッグでも、毛のある体の上ではやはり傾いて見えます。

10. その動物が現れる場所

野良は、そのチャンクが最初に読み込まれるときに、建物ごと・チャンクごとに抽選されます。抽選は手順の リストとして書きます。犬種定義の spawns の中か、CD.registerStraySpawns(リスト) のどちらかです。

spawns = {
    { id = "pughouse", class = "house", suffix = "|pg", breed = "pug", indoor = 85,
      chance = function() return CD.strayChancePerHouse() / CD.PUG_HOUSE_RARITY end },
    { id = "pugpetvet", class = "petvet", suffix = "|pv", breed = "pug",
      chance = function() return CD.PUG_PETVET_CHANCE * CD.dogSpawnMultiplier() end },
},
キー 何であるか
id 手順の名前。あなた自身のログ用です
class 抽選の対象になる建物クラス
chance パーセントを返す関数。数値ではなく関数なのは、サンドボックスの倍率にその場で追随できるようにするためです。
suffix 永続ストアのキー。エコシステム全体で一意、そして決して変えません。
breed 出現させる犬種のキー
gate 真偽値を返す任意の関数。抽選の前に見られます。ハスキーは CD.isWinter を使っています。
indoor 路上ではなく建物の中で生まれる確率。既定は 35 です。

確率には CD.dogSpawnMultiplier() を掛けるか、CD.strayChancePerHouse() を自前の希少度で割って ください。どちらでもプレイヤーのサンドボックス設定が効き続けます。生の数値を書くと効きません。

indoor は好みであって約束ではありません。そのチャンクに空いた屋内タイルがない建物では、屋外の タイルに戻ります。

建物クラス

ベースは四つ登録しており、そのまま使えます。

クラス 何に一致するか
house 店舗ではない住宅
police 警察署とその類
petvet ペットショップと動物病院
farm 農場の建物。町の外でも許されます

どれも合わないなら、自分で登録します。

CD.registerBuildingClass("mineshaft", function(def) return def:isX() end,
                         { skipUrbanGate = true })

一致関数は建物定義を受け取り、保護された呼び出しの中で走ります。ですからそこでの誤りがチャンクの 読み込みを巻き込むことはありません。skipUrbanGate は、市街地でないチャンクでもクラスが抽選される ようにします。農場や森の小屋にはこれが要ります。exclusive はそのままにしておいてください。ベースの クラス同士は排他ですが、アドオンのクラスは加算的で、その上に重ねて一致するように作られています。

すでに使われている接尾辞

接尾辞は「この建物はもう抽選済み」を保存するキーの一部です。同じ接尾辞を使う二つの Mod は、互いの 抽選を壊し合います。

接尾辞はすべて縦棒で始まります。以下はすでに使用中です。

  • ベース: 空の接尾辞と、g、h、hv、bc
  • ロットワイラー: rw、r
  • ドーベルマン: db、dm
  • ラブラドール: lb、lk
  • パグ: pg、pv
  • 猫: ct、cv、ctw、cvw、cto、cvo、ctc、cvc、ctx、cvx

誰も使っていないものを選び、そのあとは二度と触らないでください。

11. 犬種の moodle

moodle は client のファイルです。CD.DogMoodles にテーブルを足せば、ベースが描画も追跡も後始末 もします。

CD.DogMoodles[#CD.DogMoodles + 1] = {
    id = "shadow",
    breed = "pug",
    nameKey = "IGUI_PD_Moodle_Shadow",
    descKey = "IGUI_PD_Moodle_Shadow_desc",
    icon = "CD_Moodle_Shadow",
    fg = "CD_MoodShadowFG",
    tintR = 0.92, tintG = 0.52, tintB = 0.68,
    condition = function(player, dog)
        if not dog or dog:isDead() then return 0 end
        if CD.getBreed(dog) ~= "pug" then return 0 end
        if CD.isDisloyal(dog) then return 0 end
        return 1
    end,
    apply = function(player, dog, elapsedMin)
        CD.relieveMood(player, CD.moodleReliefPerMin() * elapsedMin)
    end,
}

condition はレベルを返し、「表示しない」なら 0 を返します。apply には前回の呼び出しからのゲーム 内分数が渡されるので、固定の tick を前提にせず、効果に elapsedMin を掛けてください。

アイコンは 32 から 128 ピクセルまで、六つのサイズで同梱してください。インターフェースはプレイヤー のスケーリングに合わせてサイズを選ぶので、欠けたサイズは空の四角になります。

独自 moodle はオーバーレイとして描かれます。ゲーム本体の moodle システムは Mod からの新規登録を受け 付けないからです。そこはこちらで処理済みですが、moodle が Mod 自身の帯に出てバニラのものと並ばない のはそのためです。

12. フック

ベースがサーバーで呼ぶ、関数のリストが二つあります。shared のファイルから追加してください。各 ハンドラは自分専用の保護された呼び出しの中で走るので、壊れたアドオンがベースを巻き込むことは ありません。

CD.onHuntDelivered は API 2 から。動物が獲物を飼い主の足元に置いた直後に呼ばれます。

CD.onHuntDelivered[#CD.onHuntDelivered + 1] = function(animal, owner)
    -- server side, so this is the right place to write mod data
end

CD.onUpkeepStress は API 3 から。メンテナンスのたびに、ベースが満たされない欲求のストレスを 足したあと、書き込む前に呼ばれます。数値を返すと、合計に加算されます。

CD.onUpkeepStress[#CD.onUpkeepStress + 1] = function(animal, needsStress)
    return CD.pugHeatRatio(animal) * CD.PUG_HEAT_STRESS_MAX
end

これがアドオンから動物の継続的なストレスに影響できる唯一の方法です。メンテナンスは毎周期に値を 計算し直して上書きするので、外から書いたものは次の tick で消えます。環境から来る状態、つまり暑さ、 寒さ、雨のための正しい道具です。

マルチプレイの規則を一行で。client は決して ModData を書かない。 client 側の書き込みは次の同期で server のコピーに上書きされ、症状は何分もあとに、まったく別の場所で出ます。作業は server のファイル で行うか、すでにそこで走っているこれらのフックの中で行ってください。

13. 翻訳キー

media/lua/shared/Translate/<LANG>/ の言語フォルダごとに IG_UI.json をひとつ同梱します。ベースは 十四言語を同梱しています。EN、PTBR、CH、CN、DE、ES、FR、IT、JP、KO、RU、TH、UA、VI。

犬種に必要なキー:

キー どこに出るか
IGUI_PD_Breed_<key> 犬種名。Mod のインターフェース全体で
IGUI_PD_BreedDesc_<key> 動物のカードに載る説明文
IGUI_Breed_<engineBreed> ゲーム本体の画面での犬種名
IGUI_AnimalType_<type> あなたの三つのタイプそれぞれにひとつ
種のキー 種を追加したのなら、CD.registerSpecies に渡した nounKey と youngKey
moodle のキー moodle があれば、その名前と説明 
{
    "IGUI_Breed_pug": "Pug",
    "IGUI_AnimalType_pugmale": "Pug (male)",
    "IGUI_AnimalType_pugfemale": "Pug (female)",
    "IGUI_AnimalType_pugpup": "Pug (puppy)",
    "IGUI_PD_Breed_pug": "Pug",
    "IGUI_PD_BreedDesc_pug": "The house dog: the first companion whose worth is not fighting."
}

噛みつかれる点が二つあります。翻訳文字列の中のそのままのパーセント記号は、それを表示する画面を 落とします。フォーマッタがプレースホルダとして読むからです。そしてバイトオーダーマークのついた 言語ファイルはコンパイルされず、しかもエラーは壊れているのとは別のファイルの名前を挙げます。

14. セーブが覚えているもの

あなたの識別子のうち三つは、セーブファイルに書かれ、その後ずっと読み戻されます。

  • key。あなたの動物一頭ごとに保存される犬種識別子
  • typePrefix。エンジンが保存する動物タイプを形づくるもの
  • suffix。「抽選済み」ストアのキーで、スポーン手順ごとにひとつ

この三つは公開後、決して名前を変えられません。 key を変えると、その犬種の生きている動物が すべて迷子になります。suffix を変えると、既存のすべてのセーブのすべての建物が抽選をやり直し、 何か月も遊んできた世界が突然あなたの動物であふれます。

その再抽選が役に立つ唯一の場面は、それこそが狙いのときです。CD: Cats は新しい四つの毛色にわざと新しい 接尾辞を与えました。すでに動いている世界にそれらが現れ始めるようにするためで、一方もとの黒猫は歴史的 な接尾辞を保ち、再抽選しませんでした。

その犬種の動物が生きているセーブからアドオンを外すと、その動物は失われます。 エンジンは、もはや 知らないタイプの動物を捨てます。ベースは落ちませんし、絆も犬舎もきれいに劣化しますが、動物はいなく なります。公開済みのすべてのアドオンがそうしているように、Workshop のページにそう書いてください。

未知の犬種は失敗せずに劣化します。 あなたのアドオンがなければ、ベースは何を訊かれても既定の犬種に 落とすので、あなたの Mod なしで開いたセーブも読めます。

15. 公開する前に

  • ガードがすべての Lua ファイルにあり、実際に使っている API を書いている。
  • ベースのバージョン下限が、説明文に言葉で書いてある。versionMin ではそれを言えない。
  • 最初のロードでログを読んだ。読まなければ CD.registerBreed は無言で拒否し、拒否のたびに名前付きの 一行が出る。
  • CD.defineDogParts を呼んでいる。自分の動物を一頭解体して、落ちないことを確かめる。
  • key、typePrefix、スポーンの接尾辞が一意で、この先ずっとそれでよいと思える。
  • 小型の犬種は puppySize を設定していて、子犬を実際に見て確かめた。
  • 別の種族なら CD.registerVoices を呼び、voices を埋めてある。でないと吠える。
  • moodle のアイコンが六つのサイズすべてある。
  • 同梱するすべての言語フォルダにすべてのキーがある。キーが欠けると画面に生のキーが出る。
  • 単独プレイだけでなくマルチプレイで試した。位置も所有も ModData も、あちらでは違う振る舞いをする。
  • Workshop のページに、生きた動物のいるセーブからアドオンを外さないよう警告してある。

16. よくある失敗

「動物が一向に現れない」 ほとんどの場合ガードです。あなたのアドオンが、入っているベースにない API を要求しているので、意図どおり不活性になっています。自分の API 番号を第 2 節の表と見比べてくだ さい。

「現れるが固まっている」 animset が "raccoon" でないか、モデルにクリップが足りません。どちらも 永遠に立ち止まった動物として出ます。

「黒い滲みとして描かれ、ログがあふれる」 モデルのボーンが 60 を超えています。

「解体すると落ちる」 CD.defineDogParts を呼んでいません。

「子犬が成犬の大きさで生まれる」 puppySize を設定していない小型の犬種です。この値は絶対値で、 掃引のたびに再適用されるので、タイプ側のサイズ範囲では助かりません。

「自分の犬種が二つ、互いに入れ替わり続ける」 engineBreed を共有しています。接頭辞はメッシュを 選ぶもので一族で共有できますが、engineBreed はテクスチャを選び、その一族の中で決着をつけるもの なので、犬種ごとに一意でなければなりません。

「音は鳴るが音量スライダーを無視する」 その音に対して CD.registerVoices を呼んでいません。

「単独プレイでは動くのにサーバーで挙動がおかしい」 何かが client 側で ModData を書いています。 server に移してください。

「戦闘を切ったのにゾンビと戦った」 動いているベースが API 5 より古く、そこではそのフィールドが まだ存在せず、無言で無視されました。これこそガードが劣化ではなく遮断をしなければならない場面です。
