Companion Dogs：模组制作手册

如何制作你自己的附加模组：一个新品种，或者一整个物种，作为一个独立的创意工坊模组挂接到 Companion Dogs 上。

这本手册是写给做模组的人的。如果你只想玩，你要看的是另外两本： 功能 讲狗能做什么， 品种 讲品种本身。

本手册假设你已经能读 Lua，并且已经有一个带骨骼和动画的动物模型。美术流程不在这里；第 3 节列出模型 文件必须满足的条件，仅此而已。

这是一份公开的契约。 本手册点到名字的一切，都是给模组外部调用的。这里没有点到名字的东西属于 内部实现，可能在任何版本里不加通知地改变。

1. 附加模组是什么

附加模组就是一个普通的创意工坊模组，它声明 require=CompanionDogs，并在加载时调用一个函数。它只 添加一个品种（如果共用同一个身体，也可以是几个），除此之外什么都不加。让动物表现得像个同伴的 一切，早已在基础模组里，并且是共享的。

基础模组拥有：

  • 动画状态机、动画集和骨骼
  • 跟随、寻路、战斗、狩猎、放牧、警戒、需求和日常维护
  • 全部界面：狗的窗口、环形菜单、右键菜单、狗舍、地图标记
  • 驯服、羁绊、繁殖、幼崽和混血
  • 沙盒选项，以及多人游戏中的同步

你的附加模组拥有：

  • 让你的动物区别于卡拉梅洛的那些数值
  • 它的身体模型、贴图、肖像，以及如果有的话，moodle 图标
  • 它在世界上哪里能被找到
  • 它的名字和描述，在你随包附带的每一种语言里

这个分工就是全部要点。一个品种包只是几百行 Lua，因为难的部分已经在跑了。

一个品种，一副样子。 品种就是一组数值加上一副样子。如果你想让同一种动物的两种颜色表现不同，那 就是两个品种。如果你想要两种表现相同的颜色，对基础模组来说它们仍然是两个品种（两个名字，狗舍里两 条记录），而你从一张共享的表里把它们写出来，就像 CD: Cats 用它五种毛色做的那样。

2. API 的各个版本

CD.API_VERSION 就是一个普通数字。它一直只靠增加东西而变大，所以针对旧版本写的附加模组，在更新的 基础模组上一行都不用改也照样加载。

API 基础模组版本 增加了什么
1 0.6.3 CD.registerBreed、刷新注册表、品种 moodle
2 0.6.6 huntFetchLevel、huntDeliverTimeoutMin、钩子 CD.onHuntDelivered
3 0.6.8 sentinelMult、barkNoiseMult、loyaltyDecayMult、钩子 CD.onUpkeepStress
4 0.6.9 alertModeLocked
5 0.7.0 skills、canBreed、huntMaxPrey、descKey、voices、CD.registerVoices

守卫里要写的数字，是你的附加模组真正需要的最低 API，而那张表里对应的基础模组版本，就是你在创意 工坊页面上要写的版本。从这张表里取，而不是从你写代码时基础模组恰好是什么版本：只存在于开发版里的 字段，就是你的玩家没有的字段。

缺失的字段会被静默忽略。 当字段是数值时这没问题：在旧一些的基础模组上，你的动物只是用正常音量 吠叫而已。当字段是一道禁令时就有问题了，因为那样一只永远不该战斗的猫会心安理得地冲上去打。也就是 说：数值可以降级，禁令不行。如果你的动物依赖某道禁令，就用引入它的那个 API 来守卫，让附加模组在更 旧的一切上完全不动。

3. 动手之前需要准备什么

一个蒙皮好的模型。 你的动物需要自己的 .glb，放在 media/models_X/Skinned/ 下，而那个文件必须 带着完整的 21 个 Rac_* 动画片段。片段不会在模型文件之间继承：一个只有十五个片段的模型，会给你 一只在第一次被要求做其余六个动作时就僵住的动物。模型还必须保持在 60 根骨骼以下，并且顶层节点为 单位矩阵，否则引擎每一帧都会抛异常，动物会被画成一团黑色污迹。

如果你还没有模型，仍然可以把 CD.applyDogModel 指向基础模组的某个身体，然后把其余部分全部写出来并 测试。动物看上去会像卡拉梅洛，但本手册里的每一个系统都能跑。

身体的一张贴图，以及狗舍窗口用的一张肖像。

在写任何代码之前先定一件事： 你的动物是一个*品种*，还是一个*物种*？品种是数值不同的狗。物种是 压根就没有某些工作的动物。这个差别不是外观问题，它决定你要写哪些字段，第 7 节讲的就是它。

4. 一个附加模组的文件

这是 CD: Pug，已发布的附加模组里最小的一个，只留下要紧的部分：

CompanionDogsPug/
  42/
    mod.info
    icon.png
    poster.png
    media/
      models_X/Skinned/Pug_Body.glb
      scripts/models_pug.txt
      textures/Body/Pug.png
      textures/CDPortrait_pug.png
      lua/shared/CompanionDogsPug_Breed.lua
      lua/shared/Definitions/animal/PugDefinitions.lua
      lua/shared/Definitions/animal/CompanionDogsPug_Parts.lua
      lua/client/CompanionDogsPug_Moodle.lua
      lua/shared/Translate/EN/IG_UI.json
      lua/shared/Translate/PTBR/IG_UI.json
  common/

以及 mod.info：

id=CompanionDogsPug
name=CD: Pug
description=Pugs for Companion Dogs. REQUIRES the Companion Dogs mod (0.6.8 or newer).
poster=poster.png
icon=icon.png
require=CompanionDogs
modversion=0.1.0
pzversion=42.19.0
versionMin=42.18.0

require=CompanionDogs 是关键的一行。它保证基础模组的 Lua 全部在你的之前跑完，每个阶段都是如 此：先 shared，然后 client，然后 server。没有它，你的文件可能先加载，那时每一次 CD. 调用都是在对 nil 取索引。

versionMin 无法表达"需要 Companion Dogs 0.6.8"。 那个字段是*游戏*版本的门槛，除此之外别无他 意，而 mod.info 里并不存在写依赖模组版本的字段。基础模组的下限由下一节的守卫来强制，并通过你的描述 告知玩家。把它用文字写在那里，否则玩家得到的唯一症状就是一只永远不出现的动物。

5. 版本守卫

把这段放在你附加模组每一个 Lua 文件的最上面，数字换成你的附加模组真正需要的那个：

local CD = CompanionDogs
if not (CD and CD.registerBreed and (CD.API_VERSION or 0) >= 3) then return end

基础模组缺失或者太旧时，文件在第二行就返回了。这时附加模组什么都不做：没有品种，没有刷新，没有 moodle，日志里连一行都没有。这份安静是刻意的。加载了一半的附加模组比根本没加载更糟，因为玩家会得到 一只有名字却没有行为的动物。

守卫是按文件来的，每个文件守卫自己要用的东西。PugDefinitions.lua 需要模型辅助函数，于是它守卫那 些：

if not (CompanionDogs and CompanionDogs.applyDogModel and CompanionDogs.DOG_SOUNDS) then return end

永远不要自己创建那个全局变量。 附加模组里的 CompanionDogs = CompanionDogs or {} 会把一个不存在 的基础模组变成一张搭了一半的表，于是下游每一道守卫都会在不该通过的时候通过。读那个全局变量，永远不 要往里写。

6. 注册品种

一次调用，在一个 shared 文件里：

CD.registerBreed({
    key = "pug",
    engineBreed = "pug",
    typePrefix = "pug",
    nameKey = "IGUI_PD_Breed_pug",
    litter = { 1, 2 },
    xpMult = { scent = 1.5, combat = 1, obedience = 2.0, hunt = 1.2, herding = 1.0 },
    combatPower = 0.15,
    lethalityCurve = { min = 0.40, max = 1.3 },
    canKill = false,
    canKnockdown = false,
    combatStressMult = 0.9,
    panicThreshold = 0.70,
    bagMult = 0.6,
    sentinelMult = 1.35,
    barkNoiseMult = 1.5,
    alertModeLocked = true,
    loyaltyDecayMult = 0,
    geneRange = {
        strength       = { 0.00, 0.10 },
        aggressiveness = { 0.05, 0.20 },
        resistance     = { 0.00, 0.15 },
        stress         = { 0.55, 0.85 },
    },
    spawns = {
        { id = "pughouse", class = "house", suffix = "|pg", breed = "pug",
          chance = function() return CD.strayChancePerHouse() / CD.PUG_HOUSE_RARITY end },
    },
})

这次调用把品种插入进去，注册它的三个动物类型，重建繁殖顺序好让你的动物参与杂交，并注册刷新步骤。

有问题的定义会返回 nil 而不是抛错，所以一个失误绝不会把加载一起拖垮。每一次拒绝都会打印一行点名 的日志，所以你第一次注册品种时要读日志。

必填字段

字段 是什么
key 你这个品种的标识符，在所有模组之间唯一。发布之后永不更改。
typePrefix 三个动物类型的前缀：<前缀>pup、<前缀>female、<前缀>male。它选定身体网格。
nameKey 显示名称的翻译键。
xpMult 每项技能的学习速度：scent、combat、obedience、hunt、herding。1.0 是正常值。
combatPower 它下嘴有多重。卡拉梅洛是 0.20，能打的品种在 1.0 以上。
lethalityCurve { min, max }，伤害从战斗 0 级到战斗 10 级怎样增长。
geneRange 四个基因出生时的范围：strength、aggressiveness、resistance、stress。每个都是 0 到 1 之间的 { 下限, 上限 }。

可选字段

字段 默认值 作用
engineBreed 与 key 相同 交给引擎的品种名，它选定贴图。每个品种唯一。
descKey IGUI_PD_BreedDesc_<key> 描述文本的键。当几个品种共用一段描述时，把它们指向同一个键。
litter 基础模组的值 每胎幼崽的 { 下限, 上限 }。
canKill true false 表示它能磨损丧尸，但永远不会补上致命一击。
canKnockdown false true 让它能把丧尸撞倒。
combatStressMult 1 一场打斗对它意味着多少压力。
panicThreshold 基础模组的值 它停止战斗的压力水平。panicImmune = true 表示永不停止。
bagMult 1 鞍袋容量的倍数。
puppySize 0.6 幼崽的绝对视觉缩放。小型品种必须设置它，否则幼崽一出生就是成年体型。
sentinelMult 1 乘到最终的警戒半径上。
barkNoiseMult 1 缩放警报吠叫的半径和音量。它缩放噪音，而不制造噪音：沙盒的噪音选项关掉之后，没有哪个品种会用吠叫招来丧尸。
loyaltyDecayMult 1 乘到忠诚度每日的衰减上。0 表示羁绊永不消退。
alertModeLocked false 动物被锁在全面警戒上：主人在任何地方都无法把它切到安静或静默。当吵闹的警报就是设计本身时才用。
huntFetchLevel 6 从这个狩猎等级起，它会把猎物叼回给主人。
huntDeliverTimeoutMin 5 它放弃交付之前还会尝试多少游戏分钟。
idleAnimMs 基础模组的值 待机动画窗口的长度，单位毫秒。当你的片段比狗的短时要设置它，否则循环会重新开始并在动作中途被切断。
restAnim true false 让动物在待命和守卫时保持站立，而不是趴下。
voices 狗的声音 { bark, growl, idle, wildbark, pet }。见下文。
skills、canBreed、huntMaxPrey 全部开启 结构性的禁令。第 7 节。

你加进定义里的数值和标志，可以用 CD.breedNumber(animal, 字段) 和 CD.breedFlag(animal, 字段) 读 回来。比起自己去读 CD.getBreedDef(animal).字段，优先用这两个：它们替你处理缺失的字段，而且在基础 模组变动之后依然能用。

声音

不同的物种不说同一种语言。没有 voices，你的猫会吠：

CD.registerVoices({
    CDCatMeow = "bark", CDCatGrowl = "bark", CDCatPurr = "bark",
    CDCatPet = "fx", CDCatMeowAmbient = "ambient",
})
voices = { bark = "CDCatMeow", growl = "CDCatGrowl", idle = "CDCatPurr",
           wildbark = "CDCatMeowAmbient", pet = "CDCatPet" },

CD.registerVoices 不是可有可无的装饰。没有它，声音照样会响，但会无视玩家的分类音量滑块和游戏本身 的音效音量，而这是一种没人会来报告的故障，因为什么都不像是坏了。你在 voices 里漏掉的键会回退到狗 的声音，那正是你在狗的品种上想要的，也永远不是你在另一个物种上想要的。

7. 整块关掉一个系统

五项技能就是五个系统，一一对应：

技能 它就是哪个系统
scent 警戒：察觉丧尸并提醒你
combat 打斗、守卫模式和自卫
obedience 技巧树
hunt 狩猎，外加它给主人的采集加成
herding 照看围栏里的牲畜

物种不是数值更差的狗。它是压根没有其中某些工作的动物。所以它声明自己没有什么：

skills = { combat = false, herding = false },
canBreed = false,
huntMaxPrey = "tiny",

不写或者写 true，都表示这只动物拥有该技能，所以你只需要写出你要拿掉的那些。

关掉一项技能会同时做三件事：系统永远不运行，该技能永远不获得经验，它的进度条连同命令一起从界面 上消失。三件一起。只藏进度条会让技能在没人看得到的地方继续长；只锁住系统会让进度条永远卡在零上。

canBreed = false 放在表外面，因为繁殖既没有进度条也没有经验。而且它是彻底的：这只动物不会怀孕， 永远不会被选作配偶，也不会和自己的品种繁殖。

huntMaxPrey 是一场确实存在的狩猎之内的上限，这和 hunt = false 是两码事。它接受 "tiny"（小 鼠、大鼠、松鼠）、"small"（兔子、浣熊）或 "large"（鹿，默认值，没有上限）。超过上限的猎物对你的 动物来说是隐形的：它不会去追，甚至不会去指。不在这个阶梯上的取值会回落到 "large"，并在日志里打印 一行点名的记录。

被禁的动物不会得到一个灰掉的按钮。 那个选项会从环形菜单、右键菜单和窗口里消失，服务端的拒绝也是 安静的。一个写着"它无视了命令"的光环会是谎言，因为这并不是不服从。请在你的品种描述里解释这个设计。 这也正是这些字段全都不带来新翻译键的原因。

8. 动物定义

引擎把网格绑定到动物类型上，而不是绑定到品种上，所以你的品种需要自己的三个类型。这是附加模组里 机械性的一块，最短的路是复制一个现成附加模组的文件再改名。

三个部分，放在 Definitions/animal/ 下的一个 shared 文件里：

AnimalDefinitions.stages["pug"] = {}
AnimalDefinitions.stages["pug"].stages = {}
AnimalDefinitions.stages["pug"].stages["pugpup"] = {}
AnimalDefinitions.stages["pug"].stages["pugpup"].ageToGrow = 3 * 30
AnimalDefinitions.stages["pug"].stages["pugpup"].nextStage = "pugfemale"
AnimalDefinitions.stages["pug"].stages["pugpup"].nextStageMale = "pugmale"
AnimalDefinitions.breeds["pug"].breeds["pug"].texture = "Pug"
AnimalDefinitions.breeds["pug"].breeds["pug"].textureMale = "Pug"
AnimalDefinitions.breeds["pug"].breeds["pug"].rottenTexture = "Raccoon_Rotting"
AnimalDefinitions.breeds["pug"].breeds["pug"].invIconMale = "CDDogPaw_64"
AnimalDefinitions.breeds["pug"].breeds["pug"].invIconMaleDead = "CDDogPawDead_64"
local pugfemale = {}
CD.applyDogModel(pugfemale, "Pug_Body")
CD.applyDogBehaviour(pugfemale)
pugfemale.female = true
pugfemale.babyType = "pugpup"
pugfemale.minSize = 1.5
pugfemale.maxSize = 2.0
pugfemale.minWeight = 5
pugfemale.maxWeight = 8
pugfemale.wildFleeTimeUntilDeadTimer = CD.STRAY_NO_BLEEDOUT
pugfemale.breeds = AnimalDefinitions.breeds["pug"].breeds
pugfemale.stages = AnimalDefinitions.stages["pug"].stages
pugfemale.genes = AnimalDefinitions.genome["dog"].genes
AnimalDefinitions.animals["pugfemale"] = pugfemale

基础模组给你的辅助函数：

辅助函数 它填好了什么
CD.applyDogModel(t, "Body_Model") 身体模型、骨骼、屠宰用贴图和动画集
CD.applyDogBehaviour(t) 一个同伴所需的每一个引擎行为标志
CD.applyDogAvatar(t) 动物窗口的肖像镜头
CD.DOG_SOUNDS 脚步声和拟音的共享表
CD.STRAY_NO_BLEEDOUT 让受惊的流浪动物不至于失血而死的那个值
CD.defineDogParts(typePrefix, engineBreed) 三个成长阶段的屠宰部位

四条并不显然的规则：

动画集必须保持是 "raccoon"。 CD.applyDogModel 会设置它。分叉出去的动画集不会加载它自己的状态 机，而没有状态机的动物就是一只钉在原地的动物。

复用基因组： AnimalDefinitions.genome["dog"].genes。不要自己写一份。

永远不要声明 mate。 有了它，引擎会在任何动物区域内跑它自己的原生交配，那套逻辑无视本模组的繁殖 禁令和沙盒选项，产出没有羁绊的幼崽。基础模组会在启动时清掉这个字段作为安全网，但别依赖它。

部位是必需的。 单独一个文件里三行：

if CompanionDogs and CompanionDogs.defineDogParts then
    CompanionDogs.defineDogParts("pug", "pug")
end

没有它们，屠宰你的动物会让原版代码崩溃，因为它按类型和品种去索引部位定义，然后踩到 nil。

小型动物需要调整肖像镜头。 CD.applyDogAvatar 里的肖像缩放是按狗校准的，而头像的 zoom 是放大 倍率：动物越小，数字越大。把 zoom 除以相对狗的体型比例，再把偏移量乘上这个比例，否则你的动物会小小 地缩在自己肖像的底部。

9. 模型脚本

media/scripts/ 下的一个文件，正是它告诉游戏你的模型存在：

module Base
{
    model Pug_Body
    {
        mesh = Skinned/Pug_Body,
        shader = animalEffect,
        static = false,
        animationsMesh = PugAnim,
        attachment head
        {
            offset = -0.0061 0.1671 0.0507,
            rotate = -179.0 -5.0 95.0,
            bone = Dummy01,
        }
    }

    animationsMesh PugAnim
    {
        meshFile = Skinned/Pug_Body,
        keepMeshAnimations = true,
    }
}

keepMeshAnimations = true 是让你模型文件内部的动画片段保持可用的那一行。没有它，模型能加载但永远 不会动。

head 附着点是帽子之类东西所在的位置。如果你想让鞍袋适配你的动物，就用同样的方式在脊椎骨上加 saddlebags_l、saddlebags_r 和 saddlebags_c。这些数字是在游戏里看着动物一点点挪出来的，而不是 量模型量出来的：一个数学上居中的袋子，放在带毛的身体上照样看着歪。

10. 这只动物在哪里出现

流浪动物是按建筑、按区块抽取的，就在那个区块第一次加载的时候。你把自己的抽取写成一串步骤，要么放在 品种定义里的 spawns，要么通过 CD.registerStraySpawns(列表)。

spawns = {
    { id = "pughouse", class = "house", suffix = "|pg", breed = "pug", indoor = 85,
      chance = function() return CD.strayChancePerHouse() / CD.PUG_HOUSE_RARITY end },
    { id = "pugpetvet", class = "petvet", suffix = "|pv", breed = "pug",
      chance = function() return CD.PUG_PETVET_CHANCE * CD.dogSpawnMultiplier() end },
},
键 是什么
id 这个步骤的名字，给你自己的日志用
class 它在哪个建筑类别上抽取
chance 一个返回百分比的函数。是函数而不是数字，这样它才能实时跟随沙盒倍率。
suffix 持久化存储的键。在整个生态里唯一，并且永不更改。
breed 要生成的品种键
gate 可选函数，返回布尔值，在抽取之前检查。哈士奇用的是 CD.isWinter。
indoor 在建筑内部而不是街上出生的百分比。默认 35。

把你的概率乘上 CD.dogSpawnMultiplier()，或者把 CD.strayChancePerHouse() 除以你自己的稀有度。无论 哪种方式，玩家的沙盒设置都还起作用，而你要是写一个光秃秃的数字，它就不起作用了。

indoor 是偏好而不是承诺：那个区块里没有空闲室内地块的建筑会回落到外面的地块。

建筑类别

基础模组注册了四个，你可以直接用：

类别 匹配什么
house 不是商店的住宅建筑
police 警察局之类
petvet 宠物店和兽医诊所
farm 农场建筑，并且允许出现在城镇之外

如果没有一个合适，就注册你自己的：

CD.registerBuildingClass("mineshaft", function(def) return def:isX() end,
                         { skipUrbanGate = true })

匹配函数会收到建筑定义，并在一次受保护的调用里运行，所以它里面的失误不会把区块加载拖垮。 skipUrbanGate 让这个类别可以在非城镇区块里抽取，农场或者林中小屋正需要这个。别去动 exclusive： 基础模组的那几个类别彼此互斥，而附加模组的类别设计上是叠加的，会在它们之上再匹配一层。

已经被占用的后缀

后缀是"这栋建筑已经抽过了"这条记录所用键的一部分。两个模组用同一个后缀，会互相毁掉对方的抽取结果。

每个后缀都以一根竖线开头。下面这些已经在用：

  • 基础模组： 空后缀，以及 g、h、hv、bc
  • 罗威纳： rw、r
  • 杜宾： db、dm
  • 拉布拉多： lb、lk
  • 巴哥： pg、pv
  • 猫： ct、cv、ctw、cvw、cto、cvo、ctc、cvc、ctx、cvx

挑一个没人用的，然后再也别碰它。

11. 品种 moodle

moodle 是一个 client 文件。你往 CD.DogMoodles 里追加一张表，基础模组负责绘制、跟踪和清理：

CD.DogMoodles[#CD.DogMoodles + 1] = {
    id = "shadow",
    breed = "pug",
    nameKey = "IGUI_PD_Moodle_Shadow",
    descKey = "IGUI_PD_Moodle_Shadow_desc",
    icon = "CD_Moodle_Shadow",
    fg = "CD_MoodShadowFG",
    tintR = 0.92, tintG = 0.52, tintB = 0.68,
    condition = function(player, dog)
        if not dog or dog:isDead() then return 0 end
        if CD.getBreed(dog) ~= "pug" then return 0 end
        if CD.isDisloyal(dog) then return 0 end
        return 1
    end,
    apply = function(player, dog, elapsedMin)
        CD.relieveMood(player, CD.moodleReliefPerMin() * elapsedMin)
    end,
}

condition 返回等级，或者返回 0 表示"不显示"。apply 在调用时会拿到距上次调用过去的游戏分钟数，所 以请把你的效果乘上 elapsedMin，而不要假设一个固定的心跳。

图标要随包提供六种尺寸，从 32 到 128 像素。界面会按玩家的缩放来挑尺寸，缺一个尺寸就是一个空方 块。

自定义 moodle 是作为叠加层绘制的，并不走游戏自身的 moodle 系统，因为那个系统不接受来自模组的新条 目。这一块已经替你处理好了，但这也是为什么 moodle 出现在模组自己的条带里，而不是混在原版那些中间。

12. 钩子

基础模组在服务端调用的两份函数列表。请从一个 shared 文件里往里追加。每个处理函数都在自己那次受 保护的调用里运行，所以坏掉的附加模组不会把基础模组一起拖垮。

CD.onHuntDelivered，从 API 2 开始，在动物把猎物放到主人脚边之后立刻调用：

CD.onHuntDelivered[#CD.onHuntDelivered + 1] = function(animal, owner)
    -- server side, so this is the right place to write mod data
end

CD.onUpkeepStress，从 API 3 开始，在每个维护周期里调用，时机是基础模组已经把未满足需求带来的压 力加好、还没写回去之前。返回一个数字，它会被加到总和里：

CD.onUpkeepStress[#CD.onUpkeepStress + 1] = function(animal, needsStress)
    return CD.pugHeatRatio(animal) * CD.PUG_HEAT_STRESS_MAX
end

这是附加模组能影响动物持续压力的唯一途径。维护会在每个周期重新计算并覆盖这个值，所以你从外面写 进去的任何东西，下一个心跳就没了。对于来自环境的状态，比如炎热、寒冷、下雨，这才是对的工具。

多人游戏的规则，一句话：客户端永远不写模组数据。 客户端这边的写入会在下一次同步时盖掉服务端的副 本，而症状要过几分钟才在毫不相干的地方冒出来。把这份活儿放到服务端文件里做，或者放进这些本来就跑在 服务端的钩子里。

13. 翻译键

每个语言目录下随包提供一份 IG_UI.json，路径是 media/lua/shared/Translate/<LANG>/。基础模组提供了 十四种：EN、PTBR、CH、CN、DE、ES、FR、IT、JP、KO、RU、TH、UA、VI。

一个品种需要的键：

键 显示在哪里
IGUI_PD_Breed_<key> 品种名，出现在模组界面各处
IGUI_PD_BreedDesc_<key> 动物卡片上的描述
IGUI_Breed_<engineBreed> 游戏自身界面里的品种名
IGUI_AnimalType_<type> 你那三个类型各一个
你的 moodle 键 名称和描述，如果你有 moodle 
{
    "IGUI_Breed_pug": "Pug",
    "IGUI_AnimalType_pugmale": "Pug (male)",
    "IGUI_AnimalType_pugfemale": "Pug (female)",
    "IGUI_AnimalType_pugpup": "Pug (puppy)",
    "IGUI_PD_Breed_pug": "Pug",
    "IGUI_PD_BreedDesc_pug": "The house dog: the first companion whose worth is not fighting."
}

有两件事会咬你。翻译字符串里一个字面的百分号会让显示它的那个界面崩掉，因为格式化器把它读成了占 位符。还有，带 字节顺序标记 的语言文件编译不过，而且报出来的错误点的是另一个文件的名字，不是真 正坏掉的那个。

14. 存档记住的东西

你的三个标识符会被写进存档文件，并且从此一直被读回来：

  • key，存在你每一只动物身上的品种标识符
  • typePrefix，它构成了引擎所保存的那些动物类型
  • suffix，"已经抽过了"这份存储的键，每个刷新步骤一个

这三个在发布之后都不能再改名。 改掉一个 key，会让那个品种所有还活着的动物变成孤儿。改掉一个 suffix，会让每一份现有存档里的每一栋建筑重新抽一次，一个玩了好几个月的世界会突然塞满你的动物。

这种重抽唯一有用的时候，就是它本身正是目的：CD: Cats 特意给它四种新毛色配了新后缀，正是为了让它们在 已经在跑的世界里开始出现，而原来那只黑猫保留了自己的历史后缀，没有重抽。

从一份还有该品种活体动物的存档里移除附加模组，就等于弄丢它们。 引擎会丢弃自己不再认识其类型的动 物。基础模组不会崩，羁绊和狗舍都会干净地降级，但那只动物没了。像每一个已发布的附加模组那样，把这件 事写在你的创意工坊页面上。

未知的品种是降级而不是失败。 如果你的附加模组不在，基础模组对于所有相关询问都会回落到默认品种， 所以一份没有你模组也照样打得开的存档是可读的。

15. 发布之前

  • 守卫在每一个 Lua 文件里都有，并且写的是你真正用到的那个 API。
  • 基础模组的版本下限用文字写在你的描述里。versionMin 说不出这件事。
  • 你在第一次加载时读了日志。否则 CD.registerBreed 会安静地拒绝，而每次拒绝都会打印一行点名的记 录。
  • CD.defineDogParts 确实被调用了。屠宰一只你自己的动物，看看不会崩。
  • 你的 key、typePrefix 和刷新后缀都是唯一的，而且你愿意永远用下去。
  • 小型品种设置了 puppySize，并且你亲眼见过一只幼崽来证明这一点。
  • 如果它是另一个物种，CD.registerVoices 确实被调用了并且 voices 填好了，否则它会吠。
  • moodle 图标六种尺寸都在。
  • 你随包提供的每个语言目录都有全部的键。缺一个键，屏幕上就会显示出光秃秃的键名。
  • 你在多人游戏里测过，而不只是单人。位置、归属和模组数据在那边的表现是不一样的。
  • 你的创意工坊页面警告了不要从还有活体动物的存档里移除这个附加模组。

16. 常见错误

"我的动物从来不出现。" 几乎总是守卫：你的附加模组需要一个已安装基础模组没有的 API，所以它按设计 处于不动的状态。拿你的 API 数字和第 2 节的表对一下。

"它出现了，但是僵住不动。" 动画集不是 "raccoon"，或者你的模型缺了动画片段。两者都会表现为一只 永远站着不动的动物。

"它被画成一团黑色污迹，日志刷屏。" 模型的骨骼超过 60 根。

"屠宰它会崩。" CD.defineDogParts 没被调用。

"幼崽一出生就是成年体型。" 一个没设置 puppySize 的小型品种。这个值是绝对的，而且每一轮扫描都会 重新施加，所以类型本身的尺寸范围救不了你。

"我的两个品种总是变成对方。" 它们共用了 engineBreed。前缀选的是网格，可以由一个家族共用； engineBreed 选的是贴图，正是它在那个家族内部做区分，所以它必须每个品种唯一。

"声音响了，但无视音量滑块。" 那个声音没有调用过 CD.registerVoices。

"单人里没问题，上了服务器就乱来。" 有东西在客户端写模组数据。把它挪到服务端去。

"我明明关了战斗，它还是和丧尸打起来了。" 它所运行的基础模组比 API 5 更旧，那时这个字段还不存在， 于是被安静地忽略了。这正是守卫必须拦下来、而不是降级的那种情况。
